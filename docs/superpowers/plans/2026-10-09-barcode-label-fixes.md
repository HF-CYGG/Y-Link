# 条码标签冲突与打印交互修复计划

> 本计划服务于当前已授权的本地修复。实施前保留 34 个既有脏文件；不提交、部署、改真实数据、改数据库排序规则或新增依赖。每个阶段以实际源码和验证输出为准。

## 职责与不变量

- 后端负责人只改 `backend/src/services/product.service.ts`、两个现有商品导入服务的最小互斥锁入口及条码专项验收脚本，独占后端构建产物、隔离 SQLite/MySQL 测试资源；前端负责人只改产品管理、标签打印界面及其专项验收，独占前端构建产物。共享构建和最终快照验证串行，互不覆盖既有修改。
- 产品编码、SKU 当前编码、原厂条码及历史编码保留原值。新写入须按**目标数据库实际等价关系**拒绝不同 SKU/商品的跨列碰撞；SQLite 精确比较与 MySQL 二进制排序规则不得被统一小写处理改变。单 SKU 的多字段同码和合法同批互换仍可用。
- 扫码先按“当前版本、启用状态”选最高状态层；该层跨任意匹配列命中多个不同 SKU 时失败关闭，避免条码列优先级掩盖错归属。同一 SKU 的多列命中去重后才按条码/SKU/历史编码选匹配类型；较低状态层保留既有兼容语义。旧纸签历史编码在非歧义场景继续可查。
- 前端原型以稳定的商品/SKU 标识作为勾选键，只保留本页选择；同页刷新和排序恢复勾选，分页、筛选继续沿用当前选择行为，不新增跨页勾选。小尺寸标签与高密度参数需验证内容可读、条码可扫及打印边界；打印窗口/异步图像或字体失败时给出反馈并清理临时资源，不遗留加载状态。前端不替后端决定扫码归属。

## 分阶段实施与验收

1. [x] 阅读项目总览、商品与数据模型、后端事务规范和适用 skill；保存当前 34 个脏文件的逐项哈希清单。
2. [x] 主线裁决数据库等价比较方案、既存多 SKU 同状态层碰撞的错误契约，以及两个导入服务的前置互斥锁；确认不改 schema、排序规则和公共 DTO。
3. [x] 后端真实服务回归取得预期红灯，并在当前源码上完成 MySQL 8.4 默认 ci、binary、异构列与 SQLite 对照；覆盖跨列大小写、同商品/跨商品、当前与 legacy、退役、多字段同一 SKU、既存同状态层多 SKU、旧标签、合法同批互换，以及不同 actor/两连接等待后提交。夹具只用本轮隔离库，显式禁止读取真实 `.env`。
4. [x] 服务层与两个导入事务入口已最小修改；当前冻结源码的真实服务 SQLite/MySQL 回归、`product:yz-code:verify`、`inventory:stock-management:verify` 和后端 `build` 均通过。异构 MySQL 列排序规则对提交 SKU 编码的编辑/导入/升级返回 409；不改旧列或旧码。
5. [x] 前端负责人已执行独立专项验证勾选键、选择恢复、小尺寸/密度限制与打印异常清理；前端类型检查、Vite 构建通过。完整 `verify:performance` 在预算阶段失败：总产物 4627.27 KB > 4570 KB、首屏 CSS 320.21 KB > 320 KB、OrderEntryView 32.48 KB > 32 KB；预算之后的运行时阶段未执行，不能称综合门禁通过。
6. [x] 复查受控 diff、源码哈希、测试命令及退出码；清理仅本轮自有隔离容器/卷，保留脱敏日志。独立审查已核对后端与前端源码、新专项脚本预导入 env 文件隔离门禁及末次负例、SQLite/MySQL 日志，无本轮新增阻断。主线核对 Docker owner 容器/卷均为空。性能预算失败与实物打印未验继续作为限制记录。

## 停止条件

若真实数据库等价规则无法可靠表达、现有优先语义需改变、需要迁移/修改旧编码或公共接口、隔离资源边界失效，立即停写并报主线裁决。同一问题连续两次无实质进展则停止该路径，保留原始失败证据。

当前隔离测试只证明所构造的两 actor 竞争和上述规则；没有数据库跨列唯一约束，不能宣称所有旁路写入或任意并发调度均被约束。实际纸张、扫码枪、打印机和登录后浏览器交互未由后端专项验证。
