# Issue #52 / #53 修复计划

## 目标与边界

- 普通分支 `codex/fix-issues-52-53` 基于刷新后的 `origin/main`（`74cad17`），不包含 PR #55。
- #52：购物车刷新不得静默改变用户数量或选择；下单前刷新校验，库存冲突整单拒绝。
- #53：保持同名注册拒绝及联系管理员提示，新个人注册和主动改名仅允许 2–20 位中文或英文字母，禁止数字及特殊字符；不迁移历史用户，不改变教师目录姓名、历史登录规则，未改名的历史账号仍可保存资料。
- 技术栈：Vue / Pinia / TypeScript / TypeORM；不新增依赖、不创建 worktree、不提交或推送。

## 实施顺序

1. 针对实际购物车 store 与下单校验增加失败用例，再修复刷新、恢复、选择和数量输入行为。
2. 提交时成功刷新最新商品，检查全部选中项，再固定请求快照；保留幂等及未知结果保护。
3. 对新注册引入前后端一致的字符校验，保留重名检查和管理员处理提示；回归历史账号兼容。
4. 在隔离临时 SQLite 中验证同账号、不同账号、混合商品的库存不足拒绝及并发库存不超卖。
5. 集成专项脚本，运行前后端构建、编码、路由和安全检查，按核心结算变更运行性能验证，复查 diff。

## 验收

- 库存从 5 变 1、变 0、下架或 SKU 消失，原请求数量和选择保持，页面说明阻断原因。
- 用户主动调整、取消选择或删除后才可提交；未选中无效项不阻断其他商品。
- 刷新失败不能提交；后台刷新不改变在途请求；409 不自动缩量重试。
- 同名注册仍失败并提示管理员；特殊字符注册前后端拒绝；合法注册及旧账号登录不受影响。
- 不访问或修改生产数据库，不执行真实短信发送。
