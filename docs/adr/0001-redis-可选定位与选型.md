# ADR 0001：Redis 作为可选的共享状态层

- 状态：已采纳
- 日期：2026-10-30
- 关联：`docs/版本排期-v1.6.0与v2.0.0.md` 5.1 / 5.3、`docs/project-context/51-本地联调与部署模式.md`

## 背景

Y-Link 目前的安全票据、限流与登录风控、客服 SSE 广播、客服在线态、缓存失效与后台任务调度都保存在进程内存或依赖每请求一次的数据库写事务。单实例下这些足够；要做“多实例 + 独立 MySQL”的高并发部署时，这些状态必须跨实例共享，否则出现：验证码在 A 实例签发、B 实例校验失败；限流与撞库计数被实例数稀释；客服消息只推到一个实例；后台任务被多个实例重复执行。同时 SQLite 一体化部署与 onebox 仍是主要交付形态，不能因此增加强制依赖。

## 决策

1. **客户端库选 ioredis 5**：Lua 脚本、Pub/Sub、自动重连与命令超时的成熟度与 TLS/ACL 支持满足需求。
2. **Redis 可选**：`REDIS_URL` 留空即不启用，行为与现状完全一致；仅多实例部署需要。`Y_LINK_MULTI_INSTANCE=true` 时才强制要求 MySQL、Redis 与统一的 `Y_LINK_DATA_ENCRYPTION_KEY`，缺一拒绝启动。
3. **分级降级而非一刀切**：
   - 限流与风控：回落数据库共享桶（保持跨实例共享）；
   - SSE 广播：只投递本实例，由 30 秒空闲复核与客户端重连兜底；
   - 安全票据：Redis 已配置但不可用时返回 503，不放行、不回落内存；
   - 后台任务租约：不可用时各实例照常执行，由数据库行锁兜底。
4. **Pub/Sub 至多一次 + 本地兜底**：广播不做持久化与重放，不引入 Streams；`eventId` 只保证同实例递增，前端不依赖。
5. **键前缀与加密**：所有键经 `REDIS_KEY_PREFIX`（默认 `ylink:`）拼接，不使用 ioredis 的 `keyPrefix`（它不作用于发布订阅频道）；票据键名使用 SHA-256 摘要，值整体 AES-256-GCM 加密（复用数据加密主密钥）。
6. **部署约束**：Redis >= 6.2（`GETDEL`、`SET KEEPTTL`）；只放内网，设密码/ACL，跨网 TLS；`maxmemory-policy noeviction`，写满时快速失败并降级，不静默淘汰票据。

## 备选方案

- **node-redis**：功能等价，但团队更熟悉 ioredis 的 Lua 脚本与连接事件模型，且订阅/命令连接分离的写法更直接；无决定性差异，故不切换。
- **强制必需 Redis**：会让 SQLite/onebox 小规模部署增加运维负担与故障面，与“渐进式部署”目标冲突，否决。
- **全部能力 fail-closed**：Redis 抖动时限流、广播、任务调度全部拒绝服务，可用性代价过高；只对“放行即不安全”的安全票据采用 fail-closed。
- **用 MySQL 承接全部共享状态**：已用于限流降级桶，但每请求写事务与 Pub/Sub 轮询无法支撑目标并发，仅保留为降级路径。

## 后果

- 正面：多实例下票据、限流、广播与任务租约语义一致；未配置 Redis 的部署零影响；`/health` 与管理员性能接口可观察 Redis 状态。
- 负面：多实例部署多一个需要运维的组件；Redis 故障时安全票据类接口（验证码、MFA、找回密码）不可用；广播可能丢失，需依赖兜底机制。
- 边界：数据库维护/只读模式与迁移助手仍是实例本地状态，迁移前必须缩容到单实例；反馈附件依赖共享上传目录，对象存储驱动属 v2.0 M3 后续；SQLite 只能单实例。
- 验证：`npm --prefix backend run redis:integration:verify`。
