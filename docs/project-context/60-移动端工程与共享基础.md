# Y-Link 移动端工程与共享基础

## 适用范围

- 适用于定位 `apps/mobile`、`packages/*` 和 `.github/workflows/mobile-check.yml`。
- 适用于判断当前 Mobile Bootstrap 已交付什么、哪些能力仍未配置，以及后续任务应该读取哪些 Web/后端上下文。
- 本文不授权修改 Mobile、共享包、后端、Git 或发布配置；仓库根 `AGENTS.md` 与用户当前任务始终优先。

## 当前阶段边界

第一阶段只交付 Expo 路由占位、providers、SecureStore/SQLite 基础、平台能力接口、共享包骨架和 CI。它没有新增或修改后端 API、数据库、认证会话、购物车、订单、库存、退货等业务。

相机、相册、通知、正式 Deep Link、完整 401 refresh、服务端购物车、EAS 发布、正式包名与签名均未配置、未实现。Android bundle export 只是 JavaScript bundle 静态验证，不等同于模拟器、真机、签名 APK 或商店发布验收。

## 目录与独立安装

```text
apps/mobile/
├─ app/                     Expo Router 路由与占位页面
├─ src/app/providers/       Safe Area 与 Query providers
├─ src/features/            auth/mall/cart/checkout/orders/feedback/profile 边界
├─ src/platform/            平台能力接口与未配置错误
├─ src/db/                  SQLite 打开与 user_version 迁移框架
├─ src/ui|components|theme  UI 与主题边界
├─ src/stores|sync          状态与同步边界
├─ app.config.ts            无正式包名/凭据的 Expo 配置
├─ eas.json                 无凭据的未来发布 profile 骨架
├─ package.json
└─ package-lock.json
```

当前没有 `apps/mobile/assets/` 目录；后续获得明确授权的 UI 任务可按实际资源需求创建，不能把未来目录写成当前已存在结构。

Mobile 使用独立 lockfile，是为了不把 Expo/React Native 依赖装入现有 Web 的根依赖图，也避免在第一阶段强制启用 npm workspaces。相应限制是：当前 `apps/mobile` 不能直接跨目录源码导入 `packages/*`；正式接入需要单独设计包解析和构建方式。

## 路由与 providers

- 根 `_layout` 只组合 `<AppProviders><Slot /></AppProviders>`；
- `AppProviders` 组合 `SafeAreaProvider` 与 `QueryProvider`；
- QueryClient 必须稳定复用，不能在每次 render 时重建；
- `index` 与 auth/tabs 页面只提供轻量占位导航；
- 登录、商城、订单、反馈和个人中心占位不调用真实 API，也不代表业务完成。

当前 route group 包括：

- `(auth)`：login、register、forgot-password；
- `(tabs)`：mall、orders、feedback、profile；
- 根 `index`：进入占位流程的入口。

## 本地存储边界

### SecureStore

- 只提供字符串 `get/set/delete` wrapper；
- 不实现业务 token 生命周期、refresh、logout 或 auth-store 联动；
- 禁止存密码、验证码或未经契约确认的明文长期敏感数据。

### SQLite

- 只提供数据库打开函数和基于 `PRAGMA user_version` 的迁移框架；
- 第一阶段不创建商品、购物车、订单、反馈等业务表；
- 不自动执行复杂 hydration、outbox 或跨用户缓存恢复。

## 平台能力边界

相机、相册、通知和 Deep Link 只有平台无关接口。调用未配置实现时应得到明确的 `PlatformCapabilityNotConfiguredError`，而不是静默成功。本阶段没有安装对应原生依赖，没有权限声明，也没有 `Platform.OS` 判断散落在业务页面。

## 共享包职责

| 包 | 当前职责 | 当前限制 |
| --- | --- | --- |
| `shared-types` | 跨端稳定类型的规范入口 | 空导出；未迁移 Web/后端 DTO |
| `api-client` | HTTP 契约、标准错误、Native fetch adapter、Web bridge | 401 不刷新/重放；不依赖 UI 或存储生命周期 |
| `domain` | 纯业务函数边界 | 目前为空，不搬运 Web 逻辑 |
| `validation` | auth/cart/checkout/feedback 校验模块边界 | 目前为占位，不发明正式 schema |
| `design-tokens` | 最小 colors/spacing/radius/fontSize primitive | 尚未接入 Mobile 主题 |

`packages/tsconfig.json` 独立严格检查所有共享包源码。`api-client` 使用 Node 22 的 TypeScript strip-types 模式运行无网络的 adapter 测试。

## CI

`.github/workflows/mobile-check.yml` 只在 `apps/mobile/**`、`packages/**` 或工作流自身变化时由 PR/push 触发，并支持手动执行。它只申请 `contents: read`，包含两个独立 job：

- Mobile：独立 `npm ci`、Expo 依赖一致性、SQLite migration 专项 `test:db`、typecheck、Android export；
- Foundations：根 `npm ci`、共享包 TypeScript 检查、api-client Node 测试。

CI 固定 Node `22.13.1`，不调用 Docker、服务端数据库迁移、EAS build/submit，也不读取 secrets。Mobile 没有笼统或虚假的通用 `test`，但已有 4 cases 的 SQLite migration 专项 `test:db`，CI 必须运行该真实测试。

## Antigravity 边界

Antigravity 后续只能在当前任务明确允许的 Mobile UI、组件、主题、资源和 feature mock 目录中工作。由于 shared packages 尚未接入 Mobile，Feature Mock 不能跨目录导入 `packages/*`，也不能发明正式 DTO、调用真实 API或修改本地/平台/同步基础。

## 验证命令

```bash
npm --prefix apps/mobile run dependencies:check
npm --prefix apps/mobile run test:db
npm --prefix apps/mobile run typecheck
npm --prefix apps/mobile run export:android
node ./node_modules/typescript/bin/tsc -p packages/tsconfig.json --noEmit
node --experimental-strip-types --test packages/api-client/test/*.test.ts
npm run verify:text-encoding
```

无法运行模拟器或真机时，必须明确记录设备交互、权限、平台差异和实际网络链路均未验证。
