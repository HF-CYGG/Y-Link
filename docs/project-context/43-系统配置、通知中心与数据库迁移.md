# Y-Link 系统配置、通知中心与数据库迁移

## 适用范围

- 适用于系统配置键、订单流水号、O2O 规则、验证码通道、通知中心、SQLite/MySQL 迁移和数据维护。
- 适用于定位“这个配置实际存在哪、通知为什么没发、迁移为什么不能切库”的问题。

- `backend/src/routes/system-config.routes.ts`
- `backend/src/routes/notification.routes.ts`
- `backend/src/routes/data-maintenance.routes.ts`

## 真实入口

- 系统配置入口：`system-config.routes.ts`
- 通知中心入口：`notification.routes.ts`
- 数据维护与迁移入口：`data-maintenance.routes.ts`
- 真规则源：`system-config.service.ts`、`notification.service.ts`、`database-migration.service.ts`

## 前端链路

- 系统配置页按配置分区展示：流水号、O2O 规则、客服配置、验证码通道、部门树、职工目录和统一教师邀请码。
- 统一教师邀请码配置使用 `/system-configs/client-staff-invite-code`：`GET`、`PUT`、`DELETE` 都只返回 `{ status: 'not_set' | 'enabled' | 'disabled', updatedAt }`，不回传邀请码明文；`PUT` 接收允许前导零的 8 位数字 `inviteCode`。
- 通知中心页管理规则、在线窗口、测试发送和站内收件箱。
- 数据库迁移助手页承接预检、任务创建、执行、切换、回滚和运行时覆盖状态查看。
- 自动迁移主卡片提供“测试连接”，复用受管理员门禁保护的 `POST /api/data-maintenance/db-migration/precheck`。原位展示连接失败原因、处理建议与问题码，并区分“连接成功”和“满足迁移条件”；更改主机、端口、账号、密码或库名会使旧结果失效。测试不创建任务、不导入业务数据，但会创建并移除临时表来验证基础写权限。Docker 中连接从后端容器发起，同一 Compose 的 MySQL 应使用实际服务名。
- 连接诊断专项验证：`node scripts/verify-db-migration-connection-test.mjs` 检查前端参数失效、请求乱序和取消；`node backend/node_modules/tsx/dist/cli.mjs backend/scripts/database-migration-target-issue-verify.ts` 检查错误分类与敏感信息隔离。
- 自动任务健康且状态为 `succeeded`、强校验通过、实际数据库已是 MySQL 且没有待重启配置时，主卡片显示“迁移已完成”，六阶段全部标绿并收起连接测试与迁移表单。`restart_pending`、`verifying`、失败或回退不会提前显示完成；`stage=cutover` 本身不代表完成。专项渲染和状态验证：`node scripts/verify-db-migration-completion.mjs`。

## 后端链路

- `system-config.service.ts` 维护多组 `configKey/configGroup`，重点包括：
  - 订单流水号起始值/当前值/宽度
  - O2O 自动取消、限购、门店展示文案
  - 客服在线/离线文案与 FAQ
  - 验证码移动端/邮箱通道配置
  - 客户端部门树和职工目录
  - 统一教师邀请码默认配置 `client.staff_invite_code`（首次未设置）
- 短信验证码通道默认保留 `generic_http`；切换 `aliyun_dypns` 时，阿里云 AccessKey 与手机号 HMAC 密钥只从后端环境读取，系统配置仅保存签名、可选服务名和四个场景模板码。
- `sms_verification_record` 仅保留 `outId/bizId`、HMAC 目标摘要、脱敏手机号及发送/回执/核验状态，90 天后清理；不会保存验证码或完整手机号。
- `ALIYUN_DYPNS_MNS_ENABLED=true` 时，启动完成数据库准备后会轮询固定的 `DypnsSmsVerifyReport` MNS 队列。临时 STS 由 Dybaseapi 获取且提前刷新；维护只读期暂停领取，格式错误或未知 `outId` 消息脱敏告警后确认删除，数据库或网络失败不删除消息。
- `client-staff-invite-code.service.ts` 负责统一邀请码的 HMAC 摘要、状态读取、改码与禁用，配置和审计同事务提交；注册先锁配置再锁工号，使用现有 `INVITE_CODE_PEPPER`，不兼容旧个人码。
- 首次升级需管理员在工号库顶部设置统一码；未设置或已禁用时教师新注册返回联系管理员提示，不影响已有账号登录。历史字段不删除，回退旧版本会恢复旧个人码规则。
- `notification.service.ts` 负责：
  - 默认规则补齐
  - 在线窗口配置
  - 规则更新
  - 在线态快照
  - 站内收件箱
  - 邮件与飞书外发
  - 测试发送
- `database-migration.service.ts` 负责：
  - SQLite -> MySQL 预检
  - 迁移任务落盘
  - SQLite 物理备份 + JSON 快照双备份
  - 表迁移、校验、运行时覆盖写入，以及切换前/启动失败阶段的受控恢复
- onebox 自动迁移入口为 `POST /api/data-maintenance/db-migration/automatic-tasks`：
  - 只接受目标 MySQL 的 `host/port/user/password/database` 与可选备注；
  - 自动任务固定 `DB_SYNC=false`，不接受调用方把运行时 schema 同步打开；
  - 接口返回 HTTP `202` 与脱敏任务，后续仍通过
    `GET /api/data-maintenance/db-migration/tasks/:taskId` 查询真实状态；
  - 状态至少包括 `queued/running/restart_pending/verifying/succeeded/failed/rolled_back`，
    不能把“写入覆盖、等待重启”误报为迁移成功。
- 自动迁移只在 `Y_LINK_AUTOMATIC_DB_MIGRATION_ENABLED=true` 时允许创建。普通分体后端未显式设置时保持关闭；
  onebox 入口因具备退出码 `75` 与容器重启守护，默认显式开启，也可由部署方设置为 `false` 关闭。
- 迁移期间 `/health.maintenance` 暴露可公开的
  `readOnly/phase/message` 横幅状态。普通写请求统一返回 HTTP `503`、业务码 `50301`，
  查询与健康检查继续可用；紧急回退仍保留管理员权限、CSRF 与审计门禁。
- 公开 `/health` 只返回 `status` 与脱敏维护状态，不暴露数据库拓扑、队列指标或运行时覆盖详情；
  引擎能力和写协调器水位通过管理员接口 `GET /api/data-maintenance/database/performance` 查询，
  完整运行时覆盖状态通过 `GET /api/data-maintenance/db-migration/runtime-override` 查询。
- `data-maintenance.service.ts` 负责 SQLite 备份与 JSON 导入导出。

## 自动迁移救援协议

- 自动任务仍可由局域网 HTTP 创建和观察，但明文救援凭证只会在可信 HTTPS 或真实本机连接的签发响应中返回。容器本地可运行 `node /app/backend/dist/runtime/database-rescue-cli.js rotate-credential <taskId>` 轮换指定任务的凭证。
- 凭证有效期为 24 小时；磁盘只保存 SHA-256 摘要、签发时间、源文件身份和必要快照信息。明文仅在一次签发/轮换响应或 CLI stdout 交付，轮换会使旧凭证失效，禁止写入普通应用日志。
- 受控回退只在自动迁移已冻结并已生成不可变快照后开放，且仍要求维护只读、迁移锁、任务归属和源 SQLite 文件身份。操作先取得 60 秒 nonce，再以同一任务的 `Idempotency-Key` 提交；服务验证任务/源身份/快照后先持久化恢复意图，再改任务、runtime override 和 cutover marker，重复提交同一操作只返回已有状态。
- 恢复意图的阶段固定为 `PREPARED -> RESTART_READY -> VERIFYING -> FINALIZING -> COMPLETED`：先持久化意图和摘要，再写 SQLite 覆盖与 rollback marker 并以退出码 `75` 请求重启；SQLite 启动会重新验源摘要；最终审计和启动补数完成后才收尾 marker、完成恢复意图并解除维护。
- SQLite 恢复启动失败最多自动重试一次。第二次失败后稳定停在救援态并禁止继续重放，避免无限重启掩盖故障。
- 控制文件采用原子替换、文件 `0600`（非 Windows）和目录收紧；损坏、符号链接、超大或所有权无法证明的控制文件都必须进入受限诊断。禁止删除 runtime override 或 marker 后重启碰运气。
- 救援期间不得为了绕开协议部署旧程序、降级镜像或回退到不识别当前控制文件的历史版本；这会破坏恢复日志、维护锁和数据完整性判断。

## 关键状态/字段/快照

- 流水号配置不仅有 `start/current/width`，还会做在用单号安全检查。
- 客服在线判断依赖工作时间和在线窗口秒数，而不是单纯看用户是否存在。
- 通知规则包含：站内接收人、邮件接收人、飞书 Webhook、外发时机、被监控账号列表。
- 迁移任务会落盘记录状态、进度、备份文件、校验结果和运行时覆盖是否已写入。
- onebox 使用 `Y_LINK_DATA_DIR=/app/data` 后，下列自动迁移状态都必须与 SQLite 一起落在持久化卷：
  - `runtime/maintenance-state.json`
  - `runtime/database-runtime-override.json`
  - `runtime/database-migration-cutover.json`
  - `database-migration/` 下的任务、备份与快照
- `database-migration-cutover.json` 只记录切换阶段，不保存 MySQL 密码；目标凭据只能存在于权限收紧的运行时覆盖或任务记录中，API 与日志必须脱敏。
- 严格迁移比较会保留 SQLite `sqlite_sequence` 的历史高位，包括删除过 ID 留下的序列空洞，并以 BigInt 精确处理；不得把当前表最大行 ID 当作自增序列真相。

## 权限与安全边界

- 配置读取通常是 `system_configs:view`，配置修改通常是 `system_configs:update`，高风险修改还要求 `admin`。
- `GET /api/system-configs/verification-providers/sms-receipts` 只允许 `system_configs:view`，返回记录字段均为状态与脱敏目标，不返回 AccessKey、验证码或完整手机号。
- 统一教师邀请码的设置、修改和禁用同时要求 `system_configs:update` 与 `admin`；修改或禁用须立即使旧码失效，读取接口仅可暴露状态和更新时间。
- 通知规则测试发送、数据库迁移执行、运行时覆盖切换都属于高风险治理操作。
- 飞书 Webhook、验证码通道 URL 等外部地址必须经过安全校验，不能指向危险主机。

## 常见异常与排查顺序

1. 某配置改了没生效：查实际 `configKey` 是否正确，服务层是否做了额外安全校验或缓存重建。
2. 统一教师邀请码状态异常：查 `client-staff-invite-code` 三个接口返回是否仅含状态/更新时间、写入是否同时通过权限与管理员门禁，以及旧码是否已失效。
3. 流水号改完报冲突：查系统配置服务的占用快照与预订单/出库单在用编号。
4. 通知没外发：先查规则是否命中，再查 `shouldTriggerExternal()`、接收人解析和 dispatch 记录。
5. 飞书或邮件测试发送失败：查 URL/模板/成功匹配串是否合规。
6. 迁移任务跑不动：先看 precheck，再看任务状态、校验结果和运行时覆盖状态。
7. 自动任务一直处于 `restart_pending`：确认 onebox 重启策略允许退出码 `75` 触发容器重启，并检查 `/app/data/runtime` 是否真实持久化。
8. 重启后没有进入 `verifying`：以管理员运行时状态接口返回的
   `data.effectiveDatabase` 为准检查当前进程是否真的加载 MySQL 覆盖，不要只看覆盖文件存在。
9. 自动任务失败：必须确认维护只读态已解除或进入受控恢复，禁止手工删除 marker 后直接宣称恢复。
10. MySQL 已经产生新业务写入：禁止清除运行时覆盖或直接回到旧 SQLite；应恢复 MySQL 备份或执行受控反向迁移。
11. 救援状态拒绝动作：先检查任务是否仍在维护窗口、快照和源文件是否可验证；不要通过复制旧 SQLite、清空 marker 或伪造 nonce 规避门禁。

## 验证与回归关注点

- 配置改动回归：读取、保存、回显、权限；统一教师邀请码额外确认提交后不回显明文、替换/禁用使旧码失效、状态与更新时间准确返回。
- 通知改动回归：规则列表、在线快照、测试发送、站内收件箱未读数。
- 迁移改动回归：预检、创建任务、执行任务、查看运行时覆盖、切换前取消、启动失败恢复与陈旧 SQLite 门禁。
- onebox 自动迁移改动必须运行 `npm run verify:db:migration`。真实验收标准是：
  - 隔离 SQLite 基线成功创建；
  - 全实体夹具命令确认当前全部应用实体表均包含真实记录，覆盖中文、emoji、金额、日期、空值、JSON、账号会话和实体关系；
  - 自动任务 API 返回 HTTP `202` 且任务信息不泄露密码；
  - 维护期 `/health` 横幅可见，普通写入严格返回 `503/50301`；
  - onebox 容器实际发生重启，而不是仅写入“待重启”状态；
  - 重启后 `/health` 明确显示 MySQL 运行时覆盖已生效；
  - MySQL 实际版本为 8.4、目标库为 utf8mb4，且迁移前后 `export/json` 内容一致；
  - 任务的全表强校验逐表确认非空源/目标行数、规范化 SHA-256、结构、约束与自增序列一致；其中 `sqlite_sequence` 的历史高位和已删除 ID 留下的空洞必须以 BigInt 精确保留；
  - 任一接口、状态或 Docker 前置条件缺失都必须非零失败，禁止跳过即通过。
- 2026-09-06 的真实 Docker 证据：18 个完整故障矩阵场景均已通过，包含带 30 表序列空洞的成功迁移、续跑、内容篡改拒绝、各写盘中断、稳定救援和真实 HTTP nonce/幂等回退；持续终态写盘失败保持冻结，不能为了恢复页面提前解除维护。完整场景与命令见 `docs/Web安全加固验收记录.md`，操作流程见 `docs/Web安全加固与数据库救援操作.md`。
