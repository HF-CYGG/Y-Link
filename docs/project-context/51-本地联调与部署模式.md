# Y-Link 本地联调与部署模式

## 本轮手动迁移与 npm 工具链边界

- 手动迁移开始后持续只读，直到目标启动强验收、必要补数及持久终态完成，或主动取消并安全收回控制。复制完成并非恢复营业；设置 `switchAfterSuccess=true` 也只准备切换，仍支持人工重启。等待期重启保持冻结，损坏控制进入独立救援，不回退普通业务启动。操作前保留当前任务救援凭证；SQLite 源库、任务、快照、控制文件和密钥须作为同一持久化集合保存。
- 首次切换验收仍需具备 SQLite 驱动以读取不可变源快照；不要在验收完成前改用移除 sqlite3 的 MySQL-only 镜像。这里只约束本批受控迁移流程，不执行任何业务库迁移或旧卷权限修复。
- 所有10个直接使用固定Node基础镜像的非Mobile阶段及其派生阶段、4个非Mobile CI Node作业已接同一派生工具安装器，目标实际版本为 `11.21.2-ylink.1`；Node22.23.5、Nginx1.30.6与APT验签保持原固定点。该版本是本项目基于官方npm11.21.2的源码修订，不是官方发行；安装器同时检查npm/npx实际版本，完整性不符即失败，不回退官方旧包冒称通过。接线已落盘不代表最终镜像/CI/兼容验收通过，禁止宿主全局安装或手改已部署node_modules。
- `backend/npm-toolchain/source-lock.json` 是**源码归档输入锁**，不是伪造的npm标准锁：原树以官方npm整包固定SRI/SHA256认证，不为原143个依赖编造逐包SRI；仅替换glob14.0.2、minimatch11.0.1、path-scurry3.0.0并新增nonrecursive-glob-match1.1.0，各有官方SRI。保留其余原路径/版本/字节及许可，只对不满足目标版本的消费者manifest做带前置哈希/字段期望的必要覆盖，覆盖后字节另列本地身份；最终恢复完整bundle且无overrides。应用根/后端锁不变。
- Sonar密钥job将可信构建器和安装器分别内联写入runner新私有目录，按固定模块哈希验证后执行；不会执行或import PR checkout脚本。构建器只从固定安全路径读经内联固定哈希验证的3份纯JSON数据，再消费固定官方源。每个run步骤受21,000字符契约约束，分步不放松同源算法/信任常量检查；普通镜像/无密钥job使用相同逻辑。官方旧npm仅作离线打包bootstrap，其原glob/minimatch残余仍作为构建工具风险记录，不当作已修。
- 官方npm11.21.2原包历史实际审计为144个物化包、glob/minimatch两条moderate。当前隔离组装准备得到145包/2060文件并核对归档与组装字节一致；这是准备证据，不是漏洞审计或最终安装兼容通过。双目录可复现、npm/npx、锁v3/ci/workspace/omit/ignore-scripts、pack文件选择、SQLite/sharp原生安装及实际global闭包均待统一验收；最终镜像须关联digest/SBOM/实际审计，不能只比较顶层版本或用原审计称新制品零漏洞。

## SQLite 官方源码静态重建与工具分层

- backend 默认 `npm ci/install/rebuild` 的包级 postinstall 入口为 `scripts/install-pinned-sqlite.mjs`：保留 `sqlite3@5.1.7` / TypeORM API，通过受控 `prepare/build/rebuild` 三阶段重建 SQLite3.54.1。Docker 原生依赖阶段在安装前复制入口与固定策略。归档 SHA3、amalgamation SHA3、实际 SourceID、原有扩展能力与静态依赖检查任一失败即阻断，不回退3.44.2预编译绑定，不修改SQLitemagic、数据路径或业务模型。
- 下载/编译仅在新自有目录；Linux x64/arm64 使用相同入口和目标平台工具链，Windows 使用已有VS2022子进程环境。显式 `--node-headers` 必须匹配Node22.23.5；Windows的 `--nodedir` 布局需要 `Release/node.lib`，不能用缺失库后联网猜版本或安装新工具链补齐。原型静态库不新增SQLite动态运行库。
- `verify-pinned-sqlite.mjs --project=<后端目录> --static` 通过实际内存SQL检查真正加载的引擎、SourceID、编译能力与ELF/DLL依赖，不仅比较来自头文件的VERSION/SOURCE_ID常量。Onebox 入口位于 `/app/backend/scripts/verify-pinned-sqlite.mjs`，分体 SQLite 后端位于 `/app/scripts/verify-pinned-sqlite.mjs`；`/usr/local/share/ylink-native-sqlite/` 保留三份源码/静态库/实际绑定清单。运行镜像不保留编译器，运行时可不带 `--static` 复核内存引擎，静态证据由构建清单关联。
- 只编译/类型分析和带密钥 Sonar 可显式 `--ignore-scripts`，但不能据此声称原生运行通过。真实 SQLite 文件打开前另有共用门禁，按实际驱动身份缓存成功、失败不缓存；覆盖主数据源、迁移快照、备份校验与只读救援，不提前读取业务 env。只对依赖包执行 `npm rebuild sqlite3` 不能代替包级受控入口；运行型CI恢复缓存后也必须校验实际绑定。MySQL-only 构建显式跳过/移除sqlite3且不加载它，首次切换验收仍需第6行所述的SQLite能力。当前接线已落盘，Windows/Linux隔离原型不代替本批最终安装、应用与镜像验收。
- Onebox的curl/完整gpg仅在 `nginx-keyring` 构建阶段下载并核验三把完整官方签名指纹；最终层只复制已验证keyring，保留官方HTTPS源、独立signed-by、APT/gpgv InRelease验证及固定Nginx版本。Node健康检查、后端本地救援CLI和启动监督不依赖curl/gpg。此调整不等于所有中间构建层或OS包告警已修，最终包/ELF闭包仍须实际验证。
- 系统库候选由 `backend/native-security/` 的固定源、窄补丁、构建及安装清单管理：保持Bookworm版本基线/ABI，以本地 `+ylink1` 包修订记录来源，经既有可信Debian archive keyring的InRelease→Sources→dsc/归档哈希链认证。当前源认证及接线不代表正式deb已构建/验收，也不能将libblkid局部补丁称为同包mount告警全修。系统libz不覆盖尚未验证的Node/sharp私有或静态副本；CVE归因冲突及被拦原生安全回归继续单列，不通过改版本号、关闭扫描或删除运行功能宣称全部修复。

## Onebox 后端可选非 root 模式

- `Y_LINK_ONEBOX_NON_ROOT=false` 保持默认启动行为。开启 `true` 时，`docker/onebox/backend-launcher.mjs` 在加载任何应用模块前用 Node 内置 API 清空补充组、切换镜像内 `node` 的 GID/UID 并复核真实/有效身份；API 不可用、降权不完整或卷权限不足均直接失败，不回退 root，也不引入 gosu 等依赖。
- 仅 Node 后端降权，PID 1 supervisor 与 Nginx master 保持原身份。应用仍在同一 Node PID 动态加载，因此保留 SIGTERM、退出码 75 自动切库重启和独立救援链路。权限预检失败不启动救援进程绕过权限限制。
- 启动顺序为身份切换、基础文件权限预检、原数据库控制状态恢复、有效 SQLite/WAL 权限预检、业务配置加载。基础预检不提前求值 runtime override 或缓存业务 env；可读但损坏的 override 仍由原启动边界进入稳定救援，PREPARED 恢复重放后的 SQLite 目标再用于业务数据源。
- 该模式仅支持已准备卷。镜像为新数据目录与上传目录预置 `node` 所有权；新 named volume 可继承镜像目录元数据，bind mount、tmpfs 和已有卷必须由运维先核对镜像 `node` 的实际 UID/GID，按既有变更授权自行准备。数据根、上传根必须存在，后端启动预检实际数据、SQLite/WAL/SHM、上传子目录、备份、迁移恢复控制文件及密钥所需的读写/遍历权限。
- 启动脚本不执行 chown/chmod、重建密钥或迁移旧卷。旧 root 私有卷直接改开关会失败；应先保持 `false`，备份并确认数据库与原密钥配套，在独立维护授权下准备卷，再开启并验收。回滚开关为 `false` 仅恢复启动身份，不会撤销运维自行进行的卷权限变更。
- `compose.onebox.yml` 与 `.env.onebox.example` 透传开关；外发 `compat/strict` 与 Origin JSON 白名单同时进入各后端 Compose/示例配置，不新增设置页面。

## 前端链路

- 本地联调只启动一个 Vite 开发服务器，同时承载管理端和客户端页面。
- onebox 模式下前端静态资源由 Nginx 提供，并代理后端接口与健康检查。
- 双容器模式下前端容器的健康检查同时覆盖静态页和 `/health` 代理链路。

## 后端链路

- 本地联调脚本会：
  - 清理旧 PID 和端口占用
  - 生成本次后端临时 env
  - 拉起前后端
  - 等待 `/health` 和前端端口就绪
  - 输出当前实际数据库摘要与来源
- `compose.cloud.yml` 默认仍可使用 SQLite，并要求挂载 `/app/data` 与 `/app/uploads`。
- `compose.mysql.yml` 只起应用容器，数据库由外置 MySQL 提供。
- `compose.mysql.yml` 会透传 MySQL 连接池、连接/获取/空闲超时、等待队列上限和慢查询阈值；多副本部署时需要按
  `副本数 × DB_POOL_SIZE` 计算总连接数，不能让应用连接耗尽 MySQL `max_connections`。
- 死锁与失联事务：每条 MySQL 池连接交付前会设置 `innodb_lock_wait_timeout = DB_LOCK_WAIT_TIMEOUT_SECONDS`（默认 15 秒，等待方快速失败后由下单等幂等事务退避重放，其余接口返回“数据库繁忙”503）与 `wait_timeout = DB_SESSION_WAIT_TIMEOUT_SECONDS`（默认 600 秒，且不小于 `DB_IDLE_TIMEOUT_MS` 换算秒数 + 60）。应用容器意外停止且连接被正常关闭时 MySQL 立即回滚；主机断电或网络中断导致连接悬挂时，残留的未提交事务最多在该空闲上限后被回滚并释放行锁。连接池 `maxIdle` 固定为 `DB_POOL_SIZE - 1`，使 mysql2 的空闲回收真正生效，池内连接不会空闲到被服务端断开。
- 外置或云 MySQL 不在同一可信内网时，应开启 `DB_SSL_MODE=verify-full`（校验证书链与主机名，`DB_HOST` 须与证书一致，私有 CA 用 `DB_SSL_CA` 指向容器内挂载的 PEM 文件）；`required` 只加密不校验证书，仅作过渡。该设置同样作用于运行时覆盖与 SQLite→MySQL 迁移目标库，开启后迁移目标也必须支持 TLS。默认 `disabled` 保持现有内网直连行为。
- `Dockerfile.onebox` 在同一容器内打包前端、后端与 Nginx。
- `compose.onebox.yml` 默认只启动 `ylink` 并使用 SQLite；正式启用时叠加 `compose.onebox.mysql.yml`，只追加同一私有网络中的 MySQL，
  不会启动第二套应用。数据切换必须继续走管理端自动迁移，不能直接改 env 后指向空库。
- `compose.onebox.mysql.yml` 以 `--log-bin-trust-function-creators=1` 启动 MySQL：MySQL 8.4 默认开启二进制日志，普通账号
  `CREATE TRIGGER` 会报 1419，而自动迁移需要补建 044 的账号生命周期保护触发器（只 SIGNAL 拒绝、不读写数据）。
  已在运行的内置 MySQL 需拉取新 compose 后执行 `docker compose -f compose.onebox.yml -f compose.onebox.mysql.yml up -d mysql`
  重建容器使参数生效（数据卷保留，无需迁移数据）；外置或云 MySQL 由 DBA 执行 `SET PERSIST log_bin_trust_function_creators = 1`
  或改实例参数，并给迁移账号授予目标库 `TRIGGER` 权限。不满足时自动迁移预检会在冻结写入前拒绝并给出上述提示。
- Onebox 连接 Linux 宿主机 MySQL 时使用 `host.docker.internal`（Compose 已映射 `host-gateway`）；连接远程 MySQL 时使用容器可达的 DNS/IP，禁止把数据库端口无边界暴露到公网。
- `compose.verify-db-migration.yml` 不是生产部署模板：
  - 固定 `mysql:8.4` 和独立库 `y_link_migration_verify`，与内置 MySQL 一样开启 `--log-bin-trust-function-creators=1`；
  - MySQL 不发布宿主机端口，onebox 只发布随机选择的 `127.0.0.1` 端口；
  - 两个服务只加入 `internal` 验收网络，自动任务目标固定为 `mysql:3306`；
  - 每次命令使用唯一 Compose project，创建 3 个 project 隔离卷，结束时执行
    `docker compose down --volumes`；
  - 管理员与 MySQL 验收密码每次随机生成，只注入当前脚本进程，不写入仓库、日志或 CI Secret。

## 关键状态/字段/快照

- `/health` 是公开存活与维护状态接口，只返回 `status/maintenance`，不再输出数据库摘要；确认实际数据库模式应使用管理员运行时覆盖/数据库性能接口，不以 env 或公开健康响应猜测。
- onebox 和 cloud compose 都需要考虑上传目录持久化，否则图片会随容器丢失。
- onebox Nginx 只直出 `/uploads/products/`（公开商品图）；其余 `/uploads/*` 一律代理给 Node。`uploads/client-feedback`（客户私有附件）与 `uploads/.tmp`（未校验临时文件）绝不能由 Nginx 按磁盘路径直出，附件只能经 `/api/client-feedback/attachments/:id` 与 `/api/customer-service/attachments/:id` 鉴权读取；`npm run verify:onebox:uploads` 会断言该边界。
- 运行时数据库覆盖存在时，部署模式和 `.env` 看到的值不一定等于真实生效数据库。
- onebox 自动迁移要求 `/app/data` 持久化。SQLite、迁移任务、备份、维护状态、
  cutover marker 与运行时覆盖必须位于同一持久化根目录，否则容器重启后无法继续验证或回退。
- 敏感配置加密主密钥 `secrets/data-encryption.key` 同样位于数据根目录（onebox 为 `/app/data`），空库首次使用时自动生成，启动日志 `DATA ENCRYPTION` 行回显来源与密钥 ID（不含密钥本身）。**备份数据库时必须同时备份该文件**（SQLite 物理备份结果会回显配套密钥 ID，但不会把密钥写进备份目录；未注入环境密钥且库内已有密文或有效 MFA 恢复码摘要时，缺少配套文件会以 `DATA_ENCRYPTION_KEY_MISSING` 进入救援，不生成替代密钥）；分体 MySQL 部署也要持久化后端 `/app/data`。密钥存在但 ID 不匹配时启动告警并按无法解密降级，格式损坏沿读取拒绝或降级处理，不能笼统视为不影响启动。多个后端实例共用一个 MySQL 时，改用 `Y_LINK_DATA_ENCRYPTION_KEY` 注入同一密钥。
- SQLite Onebox 只允许一个应用进程且数据库文件必须位于本地持久化磁盘；需要第二副本或持续并发写时先迁移 MySQL。
- 后端镜像（`backend/Dockerfile`、`backend/Dockerfile.mysql`）与 onebox 入口脚本默认 `UV_THREADPOOL_SIZE=8`：libuv 线程池由 scrypt、sharp、SQLite 驱动与文件读写共用，默认 4 线程在登录洪水时会饿死数据库查询。该变量必须在进程启动前由环境设置（Node 加载 ESM 入口时就可能已初始化线程池，代码内设置无效）；非容器部署需在启动命令的环境中自行设置。
- Node 服务端硬化（`backend/src/runtime/http-server-hardening.ts`，业务与救援服务共用）：`keepAliveTimeout` 65 秒（大于 onebox Nginx 上游空闲超时 50 秒，避免复用已关闭连接产生 502）、`headersTimeout` 66 秒、`requestTimeout` 120 秒（只约束接收请求阶段，抵御慢速请求攻击，不影响导出与 SSE）、`maxHeadersCount` 100。监听地址取 `Y_LINK_LISTEN_HOST`（默认 `0.0.0.0`，只接受 IP 或 localhost）；onebox 入口脚本默认 `127.0.0.1`，外部只能经 Nginx 进入，无法绕过边缘限流与请求体上限。不使用通用 `HOST` 变量，避免被 shell 自动设置的主机名误读。
- onebox Nginx 通过 `upstream ylink_backend`（`keepalive 32`、`keepalive_timeout 50s`）复用到 Node 的长连接，所有代理 location 均需 `proxy_http_version 1.1` 与清空 `Connection` 头，`npm run verify:onebox:uploads` 会断言。分体模板采用具名 upstream 与运行期 DNS 解析，详见下方部署说明。
- 三套 Nginx（`onebox.conf`、`default.conf`、`default.conf.template`）的边缘约束口径一致：登录区 12 次/分（管理端与客户端登录、两步验证第二步共用）、验证码区 30 次/分、敏感匿名区 30 次/分（注册、发码、找回校验与重置）、`/api/` 通用区每 IP 50 次/秒（突发 500），每 IP 同时处理中的请求 ≤256（`limit_conn`，空闲长连接不计）。超限返回 429、请求体超限返回 413，均为 JSON（`data.reason` 为 `EDGE_RATE_LIMITED` / `EDGE_PAYLOAD_TOO_LARGE`，429 附 `Retry-After: 5`）。请求体默认上限 1m，认证入口 64k，商品图上传、反馈附件、商品导入、教职工名录导入放宽到 11m（此前默认 1MB 会拦截 >1MB 的 GIF 与导入文件；Nginx 限制的是含 multipart 边界与字段头的整个请求体，必须略高于后端 10MB 文件上限）。校园网等大量用户共用出口 IP 时，按实际并发调大 `ylink_api_general` 的 rate/burst 与 `limit_conn`；容量型 DDoS 必须由上游 CDN/高防承担，单机限流只能削减单一来源的洪水。改动后运行 `node scripts/verify-web-edge-security.mjs`，有 Docker 时用现有镜像执行 `nginx -t`。
- 在 `/api/` 下，Web 和移动端登录、验证码、注册、发码和找回类入口共用各自的认证限流区，移动端刷新归敏感匿名区。这些入口的大小写变体与单个末尾斜杠同样受 64 KiB 限制。
- 分体模板 `default.conf.template` 通过具名 `upstream ylink_backend { zone; resolver 127.0.0.11; server backend:3001 resolve; keepalive 32; keepalive_timeout 50s; }` 代理后端：运行期解析 Docker DNS，后端未就绪时 Nginx 仍可启动（返回 502，后端就绪后自动恢复），并复用到 Node 的长连接。**禁止**写成“变量 + URI”的 `proxy_pass http://$var/api/;`：带变量时 Nginx 会用该 URI 整体替换请求路径并丢弃查询参数（实测 `/api/orders?page=2` 被转成 `/api/`，`/uploads/products/x.jpg` 被转成 `/uploads/`），`verify-web-edge-security.mjs` 已对此加断言。
- 静态资源：前端构建期为文本产物生成 `.gz`（`vite.config.ts` 的预压缩插件，仅用 Node zlib），三套 Nginx 开启 `gzip_static on`，`gzip_types` 同时覆盖 `application/javascript` 与 `text/javascript`。`public/` 下未带哈希的站点图标（favicon、apple-touch-icon、y-link-icon、icons.svg）缓存 1 天，不按 immutable 处理。`/uploads/` 接入每 IP 通用限流；分体模板对 `/uploads/products/` 做 7 天边缘缓存（`ylink_product_images`，上限 512m），onebox 继续由 Nginx 直出磁盘。
- MySQL 切换后产生第一笔新业务写入，旧 SQLite 即成为历史快照；禁止清除覆盖后直接回旧库。
- Onebox 迁移前要在 `.env` 中确定 MySQL 连接池与超时参数；运行时覆盖只保存目标库连接信息，迁移后连接池仍读取容器环境变量。
- 全新空 MySQL 可仅在第一次启动临时使用 `DB_SYNC=true` 创建当前完整实体结构，健康后必须立即改回 `false`；
  存量 MySQL 禁止开启同步，应停写、备份并按版本号执行未应用的增量 SQL。
- `backend/sql/001_init_schema.sql` 只代表历史基础结构，不能单独作为当前版本完整初始化；本轮至少按顺序执行
  `034_high_concurrency_indexes.sql`、`035_o2o_idempotency_business_sequence.sql`、`036_notification_outbox.sql`。
  `036` 会合并历史重复收件箱的已读状态并删除重复行，升级顺序必须是“备份 -> 停止所有应用/通知 Worker -> `034/035/036` -> 启动新版本”，并为索引 DDL 预留窗口；商城缓存继续复用 `030/034` 索引，本轮没有额外 catalog 结构脚本。
- 自动迁移开关 `Y_LINK_AUTOMATIC_DB_MIGRATION_ENABLED` 是部署门禁：
  - 普通分体后端未显式设置时保持关闭，因为它不保证按退出码 `75` 自动重启；
  - onebox 入口默认设置为 `true`，因为它具备计划重启与持久化恢复链路；不允许自动切换时可显式设为 `false`；
  - 验收 Compose 固定开启，但它的 internal 网络和临时卷不能复用为正式环境。

## 多实例 + 独立 MySQL + 独立 Redis

- 适用：需要多个后端实例横向扩容的高并发部署；SQLite 与 onebox 只能单实例，不适用。Redis 是**可选增强**，`REDIS_URL` 留空时行为与现状完全一致。
- 部署拓扑：负载均衡/Nginx -> N 个 `backend` 实例 -> 同一个外置 MySQL（`DB_TYPE=mysql`）+ 同一个 Redis（`REDIS_URL`）+ 共享上传目录（`/app/uploads`）。
- 叠加编排：`docker compose -f compose.mysql.yml -f compose.redis.yml up -d`（或 `compose.cloud.yml` + `compose.redis.yml`）。`compose.redis.yml` 提供 `redis:7.4-alpine`（`--requirepass`、AOF、`noeviction`、不发布宿主机端口、`REDISCLI_AUTH` 健康检查），并让 `backend` 等待 Redis 健康；onebox 为单实例，需要时自行声明 redis 服务（见该文件头注释）。
- 环境变量（定义在 `backend/src/config/env.ts`，三套 compose 的后端服务均已透传，默认空值/不启用）：
  - `REDIS_URL`：`redis://host:6379/0` 或 `rediss://host:6380`，留空不启用；`REDIS_USERNAME`（ACL 用户）、`REDIS_PASSWORD`（建议放这里而不是 URL）、`REDIS_DB`（0-15）。
  - `REDIS_TLS`（跨网开启，`rediss://` 视同开启）、`REDIS_TLS_CA`（自签 CA 的 PEM 文件路径，须挂载进容器）。
  - `REDIS_KEY_PREFIX`（默认 `ylink:`，1-32 位字母数字与 `: _ . -`，多套环境共用一个 Redis 时隔离）。
  - `REDIS_CONNECT_TIMEOUT_MS`（默认 3000）、`REDIS_COMMAND_TIMEOUT_MS`（默认 500，Redis 抖动时快速失败走降级）。
  - `Y_LINK_MULTI_INSTANCE`（默认 `false`）：为 `true` 时启动期强制 `DB_TYPE=mysql`、已配置 `REDIS_URL`、已通过 `Y_LINK_DATA_ENCRYPTION_KEY` 注入同一把数据加密密钥，缺一拒绝启动，且 Redis 首连失败也拒绝启动。
  - 注意：`REDIS_TLS`、`Y_LINK_MULTI_INSTANCE` 只接受 `true/false`，compose 默认值已写成 `false`，不要在面板里留空字符串。
- 连接数预算：`实例数 × DB_POOL_SIZE ≤ MySQL max_connections × 80%`，剩余留给运维、备份与迁移连接；每进程的连接闸门与导出并发上限仍按实例计算，不是集群总量。
- 负载均衡与 SSE：后端对 SSE 已发送 `X-Accel-Buffering: no`；Redis 启用后客服事件经 Pub/Sub 跨实例广播，**不再需要会话粘滞**。未启用 Redis 的多实例不受支持。
- Redis 安全基线：只放内网，不发布公网端口；必须设密码或 ACL；跨网必须 TLS；`maxmemory-policy noeviction`（写满时快速失败并降级，不静默淘汰票据）；版本 >= 6.2（使用 `GETDEL`、`SET KEEPTTL`），推荐 7.x；开启 AOF。
- 统一密钥：所有实例必须通过 `Y_LINK_DATA_ENCRYPTION_KEY` 注入同一把数据加密密钥（Redis 里的票据值与数据库里的敏感配置都依赖它）。
- 共享上传目录：反馈附件上传与清理依赖所有实例挂载同一个上传目录（NFS/共享卷）；对象存储驱动属 v2.0 M3 后续，当前未实现。
- 迁移前先缩容到单实例：数据库维护/只读模式与迁移助手的状态保存在实例本地，不会跨实例同步；执行迁移、数据恢复或 JSON 导入前必须先把后端缩到 1 个实例。
- 共享查询缓存：Redis 就绪时，商城目录与门店快照作为进程内缓存之后的二级缓存跨实例共享（按集群修订号即时失效），报表预览与工作台统计缓存 30 秒；只读结果、可安全降级。
- 降级策略（Redis 已配置但不可用时）：

| 能力 | 降级行为 |
|---|---|
| 限流与登录风控 | 回落到数据库共享桶 |
| SSE / 撤权广播 | 只投递本实例；30 秒空闲复核与客户端重连兜底 |
| 安全票据（验证码、MFA、重置凭证、WebAuthn 挑战等） | 返回 503，不放行（fail-closed） |
| 后台任务租约 | 各实例照常执行，由数据库行锁兜底 |
| 商城目录二级缓存、报表与工作台缓存 | 直接回源数据库，商城目录仍有进程内快照；写入失效代际递增失败时不阻塞写响应，旧缓存最多保留到其有效期 |
| 启动期 startup lock | 不可用时直接执行（多实例模式下 Redis 首连失败本就拒绝启动） |

- 观察入口：公开 `/health` 的 `redis` 字段（`disabled/connecting/ready/degraded`，不影响 `status:UP`）；管理员数据库性能接口 `GET /api/data-maintenance/database/performance` 的 `redis` 段。
- 不在范围：SQLite 多实例；跨实例的数据库维护状态；对象存储；每进程连接/导出上限的集群级统一。

## 反向代理、HTTPS 与独立救援页

- 后端的 `Y_LINK_TRUST_PROXY` 填 Node 的直接反向代理地址，例如 onebox 内部默认 `127.0.0.1,::1`，或分体 Compose 的前端固定地址；只能填写明确 IP/CIDR，不能填布尔值、跳数或 `0.0.0.0/0`。
- Nginx 的 `Y_LINK_TRUSTED_EDGE_PROXIES` 仅填写实际 TLS 终止边缘的 IP/CIDR。配置脚本只让列出的边缘决定转发协议，未列出的请求继续按当前连接协议处理。
- 对公网 HTTPS，边缘必须真实终止 TLS 并传递可信协议；可按部署需要设置 `Y_LINK_FORCE_SECURE_COOKIES=true`，并保留有效的 `Y_LINK_HSTS_MAX_AGE_SECONDS`。对仅局域网 HTTP，保持 `Y_LINK_FORCE_SECURE_COOKIES=false` 可兼容普通 Cookie 会话，但不得开放救援凭证。
- `rescue.html` 是独立 Vite 入口，Nginx 通过 `/database-rescue` 映射该页面并设置 `no-store`；它不加载普通 App、Store 或 HTTP 模块。后端进入救援态时，页面只可调用独立 `/api/database-rescue` 控制面。
- 容器内需要轮换指定任务的救援凭证时，仅运行：`node /app/backend/dist/runtime/database-rescue-cli.js rotate-credential <taskId>`。该命令不接受路径、SQL、Shell 或连接参数；其 stdout 是唯一明文交付通道，不能重定向到普通日志。
- 使用普通 HTTP 页面执行手动迁移前，先在容器本地运行 `node /app/backend/dist/runtime/database-rescue-cli.js prepare-manual-credential <taskId>` 并私下保存输出，再确认页面的本地救援准备提示。该命令仅准备未执行手动任务的凭证，不能改写活动冻结会话；远程 HTTP 签发仍拒绝。HTTPS 页面沿用可信签发并暂存当前标签，401/403 不回退绕过。
- 管理端两步验证应急重置（唯一管理员丢失认证器且恢复码用尽，或数据加密密钥丢失）：在后端运行目录执行 `node dist/runtime/admin-mfa-reset-cli.js <用户名>`（容器内为 `/app/backend`，本地开发为 `npm --prefix backend run admin-mfa:reset -- <用户名>`）。只接收用户名，按当前运行配置连库清除该账号的密码登录第二因素策略与 `second_factor` 凭据、吊销会话并写审计；`passwordless` 直接登录凭据保留。开启 TOTP 的部署必须保证服务器时间与 NTP 同步。
- MySQL 部署推荐设置 `DB_AUTO_MIGRATE=true`，升级时由启动期按白名单自动补齐新增迁移；此前一直手工执行脚本的存量库首次开启时，会先把已就位的脚本登记为基线、只执行缺口（见 `43` 的自动迁移说明），无需先手工补建 `schema_migrations`。迁移脚本按后端产物相对路径读取 `backend/sql`，onebox 镜像打包到 `/app/backend/sql`、后端独立镜像位于 `/app/sql`（均与 `dist` 同级，`verify:docker-base-image` 校验）；运行环境缺脚本时启动会在写任何迁移记录前直接失败。未开启时，新增脚本须在升级前手工执行，否则启动自检阻断并进入救援模式。
- MySQL 部署升级到含两步验证的版本时需要 `backend/sql/057_admin_mfa.sql`（已在 `DB_AUTO_MIGRATE` 白名单内）；未开启自动迁移时须先手工执行，否则启动自检会阻断并指向该脚本。SQLite 由启动期结构同步自动建表。
- 本轮新增 `backend/sql/059_admin_webauthn_second_factor.sql`：给旧凭据补 `usage='passwordless'`，给 MFA 策略补 `factor_revision=1`，并允许 TOTP 密文为空；不改写 057/058 的历史含义。MySQL 脚本可重放，但 DDL 会隐式提交，执行中断后须核查实际列定义与迁移记录再重启；`DB_AUTO_MIGRATE=true` 时由启动白名单执行，关闭时由结构契约指向 059。SQLite 旧库由启动准备阶段检查 `PRAGMA table_info` 的 `notnull`，在事务中定向重建 MFA 表、保留行/索引/外键/触发器与精确自增高位，而不是等待缺列碰巧触发全库同步。
- 多实例部署先停写旧版本节点、备份数据库及配套数据加密密钥，完成所有实例的代码与 059 结构升级后再开放新 `second_factor` 用途。旧版本不识别 `usage` 和仅通行密钥的 MFA 行，不能在已经写入新用途后直接回滚旧二进制；回退须先在受控维护窗口恢复兼容数据与对应程序版本，不能只重启旧镜像。仅通行密钥的 MFA 行仍可能有恢复码摘要，启动预检会检查其密钥 ID，缺少配套密钥时阻断启动，不得生成替代密钥。

## 权限与安全边界

- 部署文档中的环境变量不应写入真实密码。
- onebox 和 compose 都依赖后端对敏感配置的脱敏日志策略。
- 外部服务和 Webhook 仍由后端安全校验，而不是部署层兜底。

## 常见异常与排查顺序

1. 本地启动成功但页面数据不对：先看联调脚本输出的数据库摘要和 `/health`。
2. 线上图片 404：查 `/app/uploads` 是否持久化挂载。
3. 双容器前端健康检查失败：查前端是否既能访问根路径又能代理 `/health`。
4. onebox 能打开首页但接口异常：查 Nginx 代理和后端启动是否都成功。
5. 切到 MySQL 后行为还像 SQLite：查运行时覆盖和实际 `/health` 摘要。
6. 自动迁移 API 返回未启用：检查 `Y_LINK_AUTOMATIC_DB_MIGRATION_ENABLED=true` 是否注入 onebox，而不是向普通后端容器随意开放。
7. 自动迁移后容器没有重启：检查 onebox 是否保留退出码 `75`，并确认部署平台的重启策略没有被设为 `no`。
8. 验收命令在本机直接失败：先看输出属于 Docker CLI 缺失、Compose v2 缺失还是 daemon 未启动；这三类都属于真实阻断，不允许当作通过。
9. 外置 MySQL 首启提示缺表：确认目标是否真为空库；空库可在隔离首次启动阶段临时启用 `DB_SYNC=true`，存量库只能核对并补跑缺失的编号增量脚本。
10. 存量 MySQL 提示缺少 `business_sequence`、幂等列或 Outbox 索引：这是启动契约主动阻断；备份并停止全部应用/通知 Worker 后执行 `035`、`036`，不要在仍有旧实例写入时开启自动迁移。
11. 出现 `RESCUE`：确认访问为可信 HTTPS 或容器本地，再按独立救援操作说明使用任务凭证；不要将普通局域网 HTTP 当作救援本机访问，也不要手工删除 override、maintenance、cutover 或恢复意图文件。

## 验证与回归关注点

- 改本地联调脚本后回归：启动、停止、日志输出、数据库摘要、前端地址。
- 改 compose/onebox 后回归：容器健康检查、图片访问、管理端登录、客户端商城。
- WebAuthn 本地联调仅使用固定 `RP_ID=localhost` 与 `AUTH_WEBAUTHN_ORIGINS=["http://localhost:8090"]` 的示例配置；实际端口须与浏览器 Origin 完全一致，不应自动修改现有 `.env`。生产部署配置 HTTPS 的固定完整 Origin；挑战票据未配 Redis 时仅单进程内存，配置 Redis 时通过共享加密票据跨副本使用，Redis 故障返回 503。三套 Nginx 登录 location 对发现式登录 options/verify 均套用 `ylink_auth_login` 与 64k 请求体限制。
- Google Password Manager、iCloud 钥匙串等提供的是标准 WebAuthn passkey 或密码保存体验，本功能没有接入 Google/Apple OAuth。现有 RP ID、HTTPS Origin 与票据存储约束不因第二因素用途而放宽；本轮尚未取得真实 HTTPS 域名，也没有手机或物理安全密钥实测结论。
- `compose.onebox.yml` 的 `ylink` 服务和 `compose.cloud.yml` 的 `backend` 服务均显式转发 `AUTH_WEBAUTHN_ENABLED`（默认 `false`）、`AUTH_WEBAUTHN_RP_ID`、`AUTH_WEBAUTHN_RP_NAME`、`AUTH_WEBAUTHN_ORIGINS`（后三项默认空）。仅在宿主 `.env` 填写而未映射到容器环境时功能不会启用；配置后需按常规受控部署流程更新容器，本功能实施不自动部署或重建既有服务。
- 改自动迁移、运行时覆盖、维护屏障或 onebox 重启链路后，运行：

```bash
npm run verify:db:migration
```

- 可执行负向场景：

```bash
Y_LINK_DB_MIGRATION_SCENARIO=wrong-connection npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=old-version npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=wrong-charset npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=insufficient-permissions npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=non-empty-target npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=duplicate-task npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=content-tamper npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=execution-interruption npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=verifying-emergency-rollback npm run verify:db:migration
Y_LINK_DB_MIGRATION_SCENARIO=failure-rollback npm run verify:db:migration
```

- PowerShell 可使用：

```powershell
$env:Y_LINK_DB_MIGRATION_SCENARIO='wrong-connection'
npm run verify:db:migration
Remove-Item Env:Y_LINK_DB_MIGRATION_SCENARIO
```

- `content-tamper`、`execution-interruption`、`verifying-emergency-rollback`、`failure-rollback` 的确定性故障注入仅在
  `APP_PROFILE=verify-db-migration` 且 `Y_LINK_DB_MIGRATION_E2E=true` 的隔离环境启用；
  生产 profile 无法触发这些门禁。

## 商品缩略图后台资源与缓存

- 保留启动延迟 30 秒、后台并发 1 与 Y_LINK_PRODUCT_THUMBNAIL_BACKFILL=false 开关；CLI dry-run 不生成文件。
- 回填流式枚举，与上传共享图片资源闸门且不嵌套申请；读前限制 10MB，坏图逐个容错，停机取消准入并等待当前文件收尾。
- Redis 未配置按单实例运行；已配置时使用失败关闭的专用可续期租约，抢不到/降级/失租约时暂停，不能使用 runExclusive 的降级执行语义。
- 随机唯一临时文件独占创建，完成后以同目录硬链接原子发布、禁止覆盖已有目标；历史同 stem 不同扩展名冲突回退原图。
- 成功发布按最多 50 张/5 秒批次清理负缓存并通知商城目录失效，结束 flush 剩余；广播丢失由负缓存与目录 TTL 兜底。
- 分体商品图浏览器保留原缓存头，边缘有效期为 7 天；inactive=7d 表示连续未访问的缓存淘汰时间，不是有效期。512m 限额仍可能提前淘汰。
