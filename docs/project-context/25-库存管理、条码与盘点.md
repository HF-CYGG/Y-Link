# Y-Link 库存管理、条码与盘点

## 适用范围

- 适用于商品分类、库位、SKU 条码 / 成本价 / WC 编码、条码标签打印、商品 Excel 导入导出场景。
- 适用于扫码作业台（采购入库、其他出库、退货入库、报损出库、库存调整）、当前库存、通用库存流水与库存单据作废。
- 适用于库存盘点（盲盘、扫码计数、差异处理、确认调账）以及“库存为什么变成这个数”的追溯排查。

## 真实入口

- 管理端菜单“库存管理”直接展示有权限的业务页：`/inventory/scan`（扫码作业）、`/inventory/stocks`（当前库存）、`/inventory/stocktakes`（库存盘点）、`/inventory/docs`（库存单据）、`/inventory/logs`（库存流水）。父级菜单指向首个可访问业务页；工作台快捷入口使用 `/inventory`，由路由守卫按同一权限口径跳到首个可访问业务页。
- `/inventory/overview` 仅保留旧链接兼容跳转，不加载库存入口页面，也不进入菜单；`/inventory/stocktakes/:id`（盘点作业）不进菜单，侧栏高亮库存盘点。
- 分类与库位已迁入“基础资料 → 标签管理”工作台的第二个标签（`/base-data/master-data`，权限仍为 `products:view`，维护需 `products:manage`）；旧地址 `/inventory/master-data` 只做兼容重定向，不进入库存菜单，Nginx 页面白名单保留该旧路径。
- 盘点作业的当前计数项、桌面明细表与手机卡片均展示规格示例图：取服务端 `StocktakeItemRecord.thumbnail`（SKU 图优先、商品图兜底），无图时显示统一占位图且不开启预览。
- 库存业务页仍按各自权限直接访问；库存父路径和旧链接对无权限账号继续遵循管理端鉴权与回退规则。
- 产品中心：分类筛选、Excel 导入 / 导出、勾选商品打印条码；编辑弹窗维护分类，单规格商品直接维护条码、成本价、库位，多规格商品在“规格”配置里逐行维护。
- 销售出库不在这里：继续走出库开单（`manual_outbound_*` 流水）。

## 核心不变量

- 库存真值是 `base_product_sku.current_stock`；商品 `current_stock` = 当前版本且启用的 SKU 合计。
- 所有物理库存变动统一经过 `inventory-ledger.service.ts#applyInventoryDeltas`：调用方先在事务内按“商品 → SKU”加锁（`loadLockedSkuTargets`），函数负责可用量校验、整数上限、汇总同步、写后兜底，并为每个 SKU 写一条带 SKU 前后值的 `inventory_log`。
- 新增库存场景禁止在服务里手写增减；手工出库 `applyManualOutboundInventoryDeltas` 已是它的封装（流水 `changeQty` 保持出库方向为正的历史口径）。
- 送货单核销 / 冲销与 O2O 占用、释放、核销、退货、手工补货在手写记账处用 `snapshotSkuStock` + `buildSkuLogFields` 补齐 SKU 快照。
- 新建商品（含 Excel 导入）的初始库存写 `stock_initial` 流水；商品编辑改库存仍写 `manual_stock_adjust`。
- 记账函数按主键显式 `UPDATE` 库存列，不用 `save()`：MySQL 可重复读下 `save()` 以事务快照做变更比较，锁内读到的新值若等于旧快照会被跳过。
- 同一规格可分放多个库位（060）：SKU 的 `locationId` 是**主库位**，`inv_sku_location_stock` 记录主库位以外各库位的件数（同一规格同一库位一行，件数为 0 即删除）；**主库位件数 = `currentStock` − 其他库位件数之和**，不落表。主库位为空时这部分件数视为“未设置库位”。
- 库存增减与库位件数：入库、退货回补、导入等增加库存自然落在主库位，无需改动；扣减（扫码出库、手工出库与改单、盘亏报损、O2O 核销、送货单冲销、商品编辑调低库存）**先扣主库位，不够再按库位编码升序扣其他库位**，在同一事务内由 `sku-location-stock.service.ts` 的 `reconcileSkuLocationStocks` 规整，扣到的其他库位追加到流水备注（如“扣减其他库位 A-01-02×3”）。必须当场规整，不能读取时再折算（先扣后加会把入库件数算错库位）。新增扣减库存的写路径要么走 `applyInventoryDeltas`，要么改完库存后调用规整函数。
- `applyInventoryDeltas` 的增量可带 `locationId`：只增减该库位件数（按库位盘点调账用），扣减不得超过该库位现有件数。
- 库位操作（拨转、整体移入、移出、切换主库位）只搬动件数，不改变 `currentStock`、`preOrderedStock`，不写库存流水；改主库位时实物不动（原主库位剩余件数转为原主库位的拆分行，新主库位已有的拆分行并回主库位）。产品中心编辑与批量改库位修改的是主库位，原主库位剩余件数随之迁到新主库位。
- 流水查询返回带符号的 `stockDelta`（= 后 − 前）；销售出库、预订核销等历史类型的 `changeQty` 以出库为正，展示与导出统一看 `stockDelta`。

## 编号规则

- SKU 编码：商品有分类时，新规格按 `WC + 两位分类编码 + 三位流水号`（如 `WC02001`）自动生成，序列存于 `business_sequence`（键 `sku_code.WC02`），首次分配以库内已有同前缀最大号为起点，撞到手工编码时继续取下一个；存量 SKU 编码不改；无分类商品沿用 `P-YYMMDD-xxxx-DEFAULT / -SKU-n`。
- 条码：`barcode` 为原厂条码（可空、唯一、半角可打印字符）；为空时以 SKU 编码作为打印与扫码条码（Code128）。条码与 SKU 编码共用扫码命名空间，服务端拒绝任何 SKU 的条码与其他商品 SKU 的条码或编码相同；WC 流水号撞到已有条码时自动跳号。
- 商品新建、批量创建、Excel 导入、编辑与编码升级保留原编码值和数据库列排序规则，按目标数据库实际等价关系校验不同 SKU 的当前编码、原厂条码和历史编码；批量创建与 Excel 导入使用同一扫码命名空间互斥锁。MySQL 三个 SKU 编码列的排序规则不一致或不受支持时，单规格及多规格的编码写入、升级预检与提交都会安全拒绝并提示管理员处理；历史混合列数据库中，即使只编辑一个带 SKU 列表的商品也可能被拒绝，需管理员先处理排序规则，不自动改写旧编码或数据库表结构。扫码同一最高当前版本/启用状态层若命中多个不同 SKU，返回 409 提示处理冲突；同一 SKU 多列同码仍可识别，非歧义的旧纸签历史编码继续可查。
- SKU 编码是已打印标签的扫码依据，保存商品时已存在的规格一律保留原编码（单规格商品提交 `skus: []` 也不会改写）；只有新建的默认规格才回退为 `-DEFAULT`。
- 规格退役时释放条码（置空），保留规格改条码时先置空再写入，因此删除后加回、改规格名、互换条码都能保存；扫码识别合并原厂条码、当前 SKU 编码与历史 SKU 编码，优先当前版本、启用中的规格。
- 库存单据号 `KD20260917-0001`、盘点单号 `PD20260917-01`，按自然日计数。

## 后端链路

- 分类 / 库位：`GET/POST/PUT /api/inventory/categories|locations`，只停用不删除；已关联商品的分类不能改码。
- 库位关联规格：`assigned` = 主库位在此或在此拆有件数，`other` = 两者都不满足；行内返回主库位 `locationId/locationCode`、`isMainHere`、本库位件数 `locationQty`、`mainQty` 与 `otherLocations`。`GET /api/inventory/locations/:id/skus` 按 `scope=assigned|other`、商品名 / SKU 编码 / 规格文本关键词分页查询当前版本 SKU（含停用），需要 `products:manage`；`assigned` 总数与库位列表的 `skuCount` 一致。`PUT /api/inventory/locations/:id/skus/:skuId` 用 `action=assign|remove` 与必填的 `expectedLocationId`（主库位基线，可为 `null`）整体移入或移出，旧主库位变化返回 409：`assign` 把主库位全部件数搬到本库位并设为主库位（其他库位件数不动），`remove` 在本库位是主库位时清空主库位、是拆分库位时把件数并回主库位；退役 SKU 不可操作，停用库位不可新增关联。真正变更与审计在同一事务提交，重复关联不写审计。列表另支持组合筛选：`categoryId`（分类 ID，`none` 表示未分类）、`tagId`（商品关联该标签即命中，含系列标签，用 EXISTS 子查询避免多标签商品重复计数）、`status=active|inactive`（规格启停），并返回 `categoryName`；前端标签选项按 `tags:view` 懒加载，无权限时隐藏标签筛选。批量入口 `PUT /api/inventory/locations/:id/skus` 提交 `action` 与最多 100 条 `{ skuId, expectedLocationId }`，锁序为账号 → 商品 → SKU → 库位，任一条基线不一致、已退役或不属于当前库位即整批 409 回滚；逐条写 `product.location.update` 审计（`detail.batch=true`），返回实际变更数 `updatedCount`。
- 按数量拨转：`POST /api/inventory/locations/:id/skus/:skuId/transfer`（`:id` 为目标库位，需要 `products:manage`）提交 `fromLocationId`（主库位或 `null` 表示从主库位拨出）、`qty`、`expectedFromQty`（来源件数基线）、`expectedMainLocationId` 与可选 `setAsMain`；锁序账号 → 商品 → SKU → 分库位行 → 库位，来源件数或主库位与基线不一致返回 409，目标库位停用返回 400，写 `product.location.transfer` 审计（含前后分布）。`GET /api/inventory/skus/:skuId/locations` 返回单个规格的库位分布。前端 `SkuLocationTransferDialog.vue` 支持多选目标库位并逐个提交，库位管理“移入”时目标固定为当前库位并默认搬全部件数。
- 当前库存 `GET /api/inventory/stocks` 按库位筛选命中“主库位在此或在此拆有件数”，并返回 `mainLocationQty` 与 `otherLocations`。
- 扫码识别：`GET /api/products/lookup?code=` 合并原厂条码、当前 SKU 编码与历史 SKU 编码；先按当前版本、启用状态选最高层，该层命中多个不同 SKU 时返回 409，只有唯一 SKU 时才按原厂条码 > 当前 SKU 编码 > 历史 SKU 编码确定 `matchedBy`。较低状态层可在没有更高层命中时回退识别旧纸签；`purpose=stocktake` 时不返回库存数量。
- 打印数据：`POST /api/products/labels`；Excel：`GET /api/products/export`、`GET /api/products/import/template`、`POST /api/products/import/preview`、`POST /api/products/import`（只新建商品，任一行错误整批拒绝，同名多行合并为多规格）。
- 单规格商品扩展字段：商品创建 / 编辑接口的 `defaultSku`（`barcode`、`costPrice`、`locationId`）；多规格商品传 `defaultSku` 会被拒绝。
- 当前库存与流水：`GET /api/inventory/stocks`、`GET /api/inventory/logs`、`GET /api/inventory/logs/export`（上限 20000 条）。
- 库存单据：`POST /api/inventory/docs`（`clientRequestId` 幂等：同一账号且类型、原因、备注、明细完全一致才返回原单，内容不一致返回 409 并提示原单号；同一规格只能占一行）、`GET /api/inventory/docs[/:id]`、`POST /api/inventory/docs/:id/void`（生成 `stock_doc_void` 反向流水；明细规格已退役时拒绝作废，改用调整单更正）。
- Excel 导入先做真实解压体积预检（`utils/xlsx-archive-guard.ts`：条目 ≤ 2000、解压总量 ≤ 20MB，拒绝 ZIP64 与加密），再交给 exceljs；条码与 SKU 编码列在模板中为文本格式，数字格式且失真的单元格会被拒绝。
- 盘点：`POST /api/inventory/stocktakes` 建单即生成明细（状态“盘点中”）；`POST .../count`（`set` / `add` / `clear`，按库位盘点时带 `locationId`，只有一个候选库位时可省略）；`POST .../submit`（可选未盘按 0 计）；`PUT .../items/:itemId/resolution`；`POST .../reopen`（清空“重新盘点”行计数并回到盘点中）；`POST .../complete`；`POST .../cancel`。

## 盘点口径

- 账面快照在某 SKU 首次计数时由服务端记录，之后 `set`（直接录入实盘）会刷新为当前库存，`add`（连续扫码累加）沿用原快照；差异 = 实盘 − 快照；确认时按差异增量调账，盘点期间的正常出入库不会被覆盖。
- 范围外规格执行 `clear` 会直接删除该明细，不再占用该 SKU，也不会被“未盘按 0 计”算成盘亏。
- 差异处理接口未传的字段保持原值（null 表示清空），并写 `inventory.stocktake.resolve` 审计；确认时若规格在盘点期间已退役，需改为“暂不处理”。
- 按库位盘点（060）：明细按“规格 × 库位”展开（`location_scope_id` 为盘的库位，其他范围为 0，唯一键 `(stocktake_id, sku_id, location_scope_id)`）；范围内规格 = 主库位在所选库位或在所选库位拆有件数；账面快照取该库位件数（未计数时列表按该库位当前件数展示），确认调账只增减该库位件数（主库位的行随总库存变化）；盘点单返回 `scopeLocations` 供作业页选择“当前盘点库位”，计数与表格内修改 / 清除按行自己的库位提交。
- “同一 SKU 不能进两张未完成盘点单”（按库位盘点放宽为：不同库位的按库位盘点可并行，与按总量盘点或同一库位盘点冲突）：建单与追加范围外规格都先获取 `business_sequence` 上的互斥行（`inv_stocktake.scope_mutex`），明细用加锁读检查；计数时冲突检查先于锁 SKU，避免与确认盘点互相等待。
- 处理方式：调整库存（盘盈 `stocktake_gain` / 盘亏 `stocktake_loss`）、报损（`stocktake_damage`，仅限盘亏）、重新盘点（必须先退回重盘才能确认）、暂不处理（不调账）。
- 同一 SKU 不能同时出现在两张未完成（盘点中 / 待确认）的盘点单里重复调账（不同库位的按库位盘点除外）；扫码加入范围外 SKU 时同样检查。
- 盘亏受“可用库存 = 物理库存 − 预订占用”限制，存在未核销预订占用时需先处理占用。

## 权限与安全边界

- 新权限码：`inventory:view`、`inventory:operate`、`inventory:void`、`stocktake:view`、`stocktake:count`、`stocktake:approve`、`products:import`。admin 拥有全部；operator 默认 `inventory:view/operate`、`stocktake:view/count`。
- 盲盘：账面数、差异、处理信息只下发给拥有 `stocktake:approve` 的账号，计数接口永不返回账面数。角色权限固定，operator 仍可通过产品中心、当前库存看到库存，盲盘约束的是盘点作业界面与接口本身。
- 成本价只对拥有 `products:manage` 的账号可见：商品列表 / 分页 / 详情 / 扫码识别 / 导出、当前库存都会按此裁剪；`BaseProductSku#toJSON` 兜底去掉成本价，实体被直接 JSON 化（如送货单详情带出的 SKU）时不会下发。
- 所有写操作在同一事务内写审计：`product.category.*`、`product.location.*`、`product.import`、`inventory.doc.*`、`inventory.stocktake.*`（计数不单独审计）。
- 多个模块共用的只读字典（分类、库位、扫码识别）使用 `requireAnyPermission`，已纳入路由权限契约检查。

## 前端要点

- 扫码枪按 HID 键盘模式识别（`useBarcodeScanInput`：字符间隔 < 50ms + 回车）。焦点分四类：专用扫码框（`data-barcode-scan-input`）回车统一回调；数量框（`data-barcode-scan-qty` 或 number 输入）识别到扫码节奏时撤销写入并按扫码处理；备注、搜索等可编辑文本不拦截；只读下拉框、单选、页签等其他焦点照常识别。扫码结果经 `useSerialScanQueue` 串行处理，连扫不丢码；确认弹窗打开或提交中暂停入单。摄像头扫码复用 `useCameraQrScanner`，启用 CODE_128 / EAN / UPC / CODE_39 格式。
- 扫码作业台的 `clientRequestId` 在提交成功或收到 4xx 后更换，网络错误、超时、5xx 时保留以便安全重试。
- JsBarcode 只在 `BarcodeLabelPrintDialog` 内动态加载（`barcode` 低频块）；打印只在打印期间给 body 加 `y-link-print-barcode`，热敏模板每张一页，A4 模板按行列排版。
- 标签打印以手动宽高为纸张真源（宽 20–120mm、高 10–120mm），加载、模板切换、显示项和打印均不反写尺寸；四模板按已选字段和首选字号自动缩小内部字号、行高、内边距与间距，首选字号可在“每个份数”右侧设为 4–24pt，旧本机设置默认 9pt。A4 单元格净宽、净高额外扣除四边各 0.2mm 的边框，并在尺寸或手工行列变化后仅自动减少越界行列，限制在 194×281mm 可打印区域内；打印前复核并显示实际尺寸、排版。Code128 保留原编码及两侧各 10X 静区；最窄模块低于 0.25mm 或图形高度低于 8mm 时提示实机扫码风险，不擅自改码、隐藏已选字段或改变纸张，基本条码空间不足、条码生成失败或缺码仍阻断。可读编码文字默认显示，旧本机设置保持该默认值；隐藏文字不改变条码 SVG 和扫码值，并释放一行净高。文字保持单行且完整缩放；清空、切换规格或条码来源后，迟到的数据与条码图不能回填旧批次。203 DPI 下 0.25mm 约为两点，30mm 长旧码可能不足一点，软件预览或反解不能代替纸型、打印机和扫码枪实测；修改模板 CSS 后需同步校正净高和密度估算模型。
- 打印弹窗载入后在“打印规格”区按商品 ID（`POST /api/products/labels` 返回的 `productId`，商品名称不唯一不能代替）分组列出本批全部规格并默认全选，可整体、按商品或逐个规格勾选；份数、张数上限、告警、阻断、预览与打印只针对已选规格，未勾选规格的条码异常不阻断打印。条码图仍按整批生成，切换勾选不重新请求接口；勾选状态不写入本机设置，新批次重置为全选。产品中心勾选商品后会带出其全部当前规格，需只打部分规格时在弹窗内取消勾选。
- 产品中心的导入与打印弹窗均为异步组件。

## 常见异常与排查顺序

- 扫码“未找到”：确认条码是否写在 SKU 的 `barcode`，或 SKU 编码是否一致；退役规格（`is_current=0`）不能做库存操作。
- 出库 / 报损“可用库存不足”：检查预订占用 `pre_ordered_stock`。
- 盘点建单提示“正在盘点单中”：先完成或取消另一张未完成的盘点单。
- 库存对不上：按 `GET /api/inventory/logs?skuId=` 查看该 SKU 的完整流水链（旧流水可能没有 SKU 快照，页面退回显示商品汇总库存）。

## 临时打印库位（#178）

- POST `/api/products/labels` 保留 `products:view`、1..500 和原顺序/旧字段；每条新增 `printLocations`。
- `full` 还要求 `products:manage`、`inventory:view`、`stocktake:view` 任一。候选含 `locationId/locationCode/isMain/qty` 与稳定 `distributionKey`；主库位 0 件可选，其他仅正件数。完整分布先计算再过滤停用/缺失库位，过滤项仍扣除主库位件数并进入指纹。
- `main_only` 只返回主库位 ID/编码/有效性与主候选 ID/编码/isMain，不查询分库位行，不返回 qty、其他库位或完整指纹。旧 `locationCode` 始终是真实主库位。
- 前端按 SKU 维护本批临时库位，不写实际 SKU 或持久缓存。打印前同批复读；基础标签、能力、主库位或 full 完整分布变化时中止，保留仍有效的选择，失效选择留空，刷新后须确认/重选。
- 四模板预览共用派生库位；打印冻结标签、选择、份数、设置、SVG，nextTick 后复查会话仍有效才调用 window.print。份数仍为所选 SKU × copies，选择库位不改变条码内容来源。
