# Y-Link 库存管理、条码与盘点

## 适用范围

- 适用于商品分类、库位、SKU 条码 / 成本价 / WC 编码、条码标签打印、商品 Excel 导入导出场景。
- 适用于扫码作业台（采购入库、其他出库、退货入库、报损出库、库存调整）、当前库存、通用库存流水与库存单据作废。
- 适用于库存盘点（盲盘、扫码计数、差异处理、确认调账）以及“库存为什么变成这个数”的追溯排查。

## 真实入口

- 管理端菜单“库存管理”：`/inventory/scan`（扫码作业）、`/inventory/stocks`（当前库存）、`/inventory/stocktakes`（库存盘点）、`/inventory/stocktakes/:id`（盘点作业，不进菜单）、`/inventory/docs`（库存单据）、`/inventory/logs`（库存流水）、`/inventory/master-data`（分类与库位）。
- 产品中心：分类筛选、Excel 导入 / 导出、勾选商品打印条码；编辑弹窗维护分类，单规格商品直接维护条码、成本价、库位，多规格商品在“规格”配置里逐行维护。
- 销售出库不在这里：继续走出库开单（`manual_outbound_*` 流水）。

## 核心不变量

- 库存真值是 `base_product_sku.current_stock`；商品 `current_stock` = 当前版本且启用的 SKU 合计。
- 所有物理库存变动统一经过 `inventory-ledger.service.ts#applyInventoryDeltas`：调用方先在事务内按“商品 → SKU”加锁（`loadLockedSkuTargets`），函数负责可用量校验、整数上限、汇总同步、写后兜底，并为每个 SKU 写一条带 SKU 前后值的 `inventory_log`。
- 新增库存场景禁止在服务里手写增减；手工出库 `applyManualOutboundInventoryDeltas` 已是它的封装（流水 `changeQty` 保持出库方向为正的历史口径）。
- 送货单核销 / 冲销与 O2O 占用、释放、核销、退货、手工补货在手写记账处用 `snapshotSkuStock` + `buildSkuLogFields` 补齐 SKU 快照。
- 新建商品（含 Excel 导入）的初始库存写 `stock_initial` 流水；商品编辑改库存仍写 `manual_stock_adjust`。
- 记账函数按主键显式 `UPDATE` 库存列，不用 `save()`：MySQL 可重复读下 `save()` 以事务快照做变更比较，锁内读到的新值若等于旧快照会被跳过。
- 流水查询返回带符号的 `stockDelta`（= 后 − 前）；销售出库、预订核销等历史类型的 `changeQty` 以出库为正，展示与导出统一看 `stockDelta`。

## 编号规则

- SKU 编码：商品有分类时，新规格按 `WC + 两位分类编码 + 三位流水号`（如 `WC02001`）自动生成，序列存于 `business_sequence`（键 `sku_code.WC02`），首次分配以库内已有同前缀最大号为起点，撞到手工编码时继续取下一个；存量 SKU 编码不改；无分类商品沿用 `P-YYMMDD-xxxx-DEFAULT / -SKU-n`。
- 条码：`barcode` 为原厂条码（可空、唯一、半角可打印字符）；为空时以 SKU 编码作为打印与扫码条码（Code128）。条码与 SKU 编码共用扫码命名空间，服务端拒绝任何 SKU 的条码与其他商品 SKU 的条码或编码相同；WC 流水号撞到已有条码时自动跳号。
- SKU 编码是已打印标签的扫码依据，保存商品时已存在的规格一律保留原编码（单规格商品提交 `skus: []` 也不会改写）；只有新建的默认规格才回退为 `-DEFAULT`。
- 规格退役时释放条码（置空），保留规格改条码时先置空再写入，因此删除后加回、改规格名、互换条码都能保存；扫码识别合并条码与编码两路结果，优先当前版本、启用中的规格。
- 库存单据号 `KD20260917-0001`、盘点单号 `PD20260917-01`，按自然日计数。

## 后端链路

- 分类 / 库位：`GET/POST/PUT /api/inventory/categories|locations`，只停用不删除；已关联商品的分类不能改码。
- 扫码识别：`GET /api/products/lookup?code=`，合并条码与 SKU 编码两路结果，优先当前版本、启用中的规格，同等条件下条码优先；`purpose=stocktake` 时不返回库存数量。
- 打印数据：`POST /api/products/labels`；Excel：`GET /api/products/export`、`GET /api/products/import/template`、`POST /api/products/import/preview`、`POST /api/products/import`（只新建商品，任一行错误整批拒绝，同名多行合并为多规格）。
- 单规格商品扩展字段：商品创建 / 编辑接口的 `defaultSku`（`barcode`、`costPrice`、`locationId`）；多规格商品传 `defaultSku` 会被拒绝。
- 当前库存与流水：`GET /api/inventory/stocks`、`GET /api/inventory/logs`、`GET /api/inventory/logs/export`（上限 20000 条）。
- 库存单据：`POST /api/inventory/docs`（`clientRequestId` 幂等：同一账号且类型、原因、备注、明细完全一致才返回原单，内容不一致返回 409 并提示原单号；同一规格只能占一行）、`GET /api/inventory/docs[/:id]`、`POST /api/inventory/docs/:id/void`（生成 `stock_doc_void` 反向流水；明细规格已退役时拒绝作废，改用调整单更正）。
- Excel 导入先做真实解压体积预检（`utils/xlsx-archive-guard.ts`：条目 ≤ 2000、解压总量 ≤ 20MB，拒绝 ZIP64 与加密），再交给 exceljs；条码与 SKU 编码列在模板中为文本格式，数字格式且失真的单元格会被拒绝。
- 盘点：`POST /api/inventory/stocktakes` 建单即生成明细（状态“盘点中”）；`POST .../count`（`set` / `add` / `clear`）；`POST .../submit`（可选未盘按 0 计）；`PUT .../items/:itemId/resolution`；`POST .../reopen`（清空“重新盘点”行计数并回到盘点中）；`POST .../complete`；`POST .../cancel`。

## 盘点口径

- 账面快照在某 SKU 首次计数时由服务端记录，之后 `set`（直接录入实盘）会刷新为当前库存，`add`（连续扫码累加）沿用原快照；差异 = 实盘 − 快照；确认时按差异增量调账，盘点期间的正常出入库不会被覆盖。
- 范围外规格执行 `clear` 会直接删除该明细，不再占用该 SKU，也不会被“未盘按 0 计”算成盘亏。
- 差异处理接口未传的字段保持原值（null 表示清空），并写 `inventory.stocktake.resolve` 审计；确认时若规格在盘点期间已退役，需改为“暂不处理”。
- “同一 SKU 不能进两张未完成盘点单”：建单与追加范围外规格都先获取 `business_sequence` 上的互斥行（`inv_stocktake.scope_mutex`），明细用加锁读检查；计数时冲突检查先于锁 SKU，避免与确认盘点互相等待。
- 处理方式：调整库存（盘盈 `stocktake_gain` / 盘亏 `stocktake_loss`）、报损（`stocktake_damage`，仅限盘亏）、重新盘点（必须先退回重盘才能确认）、暂不处理（不调账）。
- 同一 SKU 不能同时出现在两张未完成（盘点中 / 待确认）的盘点单里，避免重复调账；扫码加入范围外 SKU 时同样检查。
- 盘亏受“可用库存 = 物理库存 − 预订占用”限制，存在未核销预订占用时需先处理占用。

## 权限与安全边界

- 新权限码：`inventory:view`、`inventory:operate`、`inventory:void`、`stocktake:view`、`stocktake:count`、`stocktake:approve`、`products:import`。admin 拥有全部；operator 默认 `inventory:view/operate`、`stocktake:view/count`。
- 盲盘：账面数、差异、处理信息只下发给拥有 `stocktake:approve` 的账号，计数接口永不返回账面数。角色权限固定，operator 仍可通过产品中心、当前库存看到库存，盲盘约束的是盘点作业界面与接口本身。
- 成本价只对拥有 `products:manage` 的账号可见：商品列表 / 分页 / 详情 / 扫码识别 / 导出、当前库存都会按此裁剪；`BaseProductSku#toJSON` 兜底去掉成本价，实体被直接 JSON 化（如送货单详情带出的 SKU）时不会下发。
- 所有写操作在同一事务内写审计：`product.category.*`、`product.location.*`、`product.import`、`inventory.doc.*`、`inventory.stocktake.*`（计数不单独审计）。
- 多个模块共用的只读字典（分类、库位、扫码识别）使用 `requireAnyPermission`，已纳入路由权限契约检查。

## 前端要点

- 扫码枪按 HID 键盘模式识别（`useBarcodeScanInput`：字符间隔 < 50ms + 回车）。焦点分四类：专用扫码框（`data-barcode-scan-input`）回车统一回调；数量框（`data-barcode-scan-qty` 或 number 输入）识别到扫码节奏时撤销写入并按扫码处理；备注、搜索等可编辑文本不拦截；只读下拉框、单选、页签等其他焦点照常识别。扫码结果经 `useSerialScanQueue` 串行处理，连扫不丢码；确认弹窗打开或提交中暂停入单。摄像头扫码复用 `useCameraQrScanner`，启用 CODE_128 / EAN / UPC / CODE_39 格式。
- 扫码作业台的 `clientRequestId` 在提交成功或收到 4xx 后更换，网络错误、超时、5xx 时保留以便安全重试。
- JsBarcode 只在 `BarcodeLabelPrintDialog` 内动态加载（`barcode` 低频块）；打印只在打印期间给 body 加 `y-link-print-barcode`，热敏模板每张一页，A4 模板按行列排版。
- 产品中心的导入与打印弹窗均为异步组件。

## 常见异常与排查顺序

- 扫码“未找到”：确认条码是否写在 SKU 的 `barcode`，或 SKU 编码是否一致；退役规格（`is_current=0`）不能做库存操作。
- 出库 / 报损“可用库存不足”：检查预订占用 `pre_ordered_stock`。
- 盘点建单提示“正在盘点单中”：先完成或取消另一张未完成的盘点单。
- 库存对不上：按 `GET /api/inventory/logs?skuId=` 查看该 SKU 的完整流水链（旧流水可能没有 SKU 快照，页面退回显示商品汇总库存）。
