# Y-Link——智能库存与订单协同管理系统需求分析说明书

## 1. 业务范围

商品有多规格，供应送货、入库、库存余额和线上预订发生在不同岗位。系统将主数据、库存、单据、预订单和客服会话放在同一套 Web 服务中，减少重复录入和状态不一致。

## 2. 角色与权限边界

| 角色 | 可用业务 | 不可替代的服务端约束 |
| --- | --- | --- |
| 管理员/操作员 | 商品、库存、入出库、报表、用户、配置、审计、客服 | 认证、权限、CSRF、高风险删除密码 |
| 供应方 | 提交、修改、撤销本人送货单，查看历史 | 仅访问供应方路由；状态和明细由服务端校验 |
| 客户端用户 | 商城、购物车、预订单、取消、退货、反馈 | 客户端鉴权、订单归属、SKU/库存/状态复核 |
| 客服人员 | 会话查询、回复、指派、内部备注 | 管理端权限和会话数据范围校验 |

## 3. 功能需求

| 编号 | 功能 | 输入 | 输出/约束 |
| --- | --- | --- |
| R1 | 商品与 SKU | 产品、标签、规格、价格、上下架信息 | 当前有效 SKU 才能参与商城下单；历史订单保存快照 |
| R2 | 供应送货 | 预计送达时间、至少一条商品明细、备注 | 生成唯一展示单号和核验码，进入 `pending` |
| R3 | 入库与库存 | 核验码、库存单据、盘点范围及实盘数 | 入库、盘点和调整形成库存流水；库存余额可查询 |
| R4 | 普通出库 | 出库明细、幂等键、版本信息 | 校验可用量，事务内写单据和流水，重复提交不重复扣减 |
| R5 | O2O 预订单 | 请求键、提货人、订单类型、明细 | 校验可用库存并预占；核销关联正式出库 |
| R6 | 反馈客服 | 会话、消息、附件、指派与备注 | 客户和客服按身份访问，会话处理过程可追溯 |
| R7 | 系统治理 | 用户、角色、配置、审计筛选条件 | 受保护路由、审计记录和外部地址安全校验 |

## 4. 关键状态

| 对象 | 状态/动作 | 规则 |
| --- | --- | --- |
| 送货单 | `pending → verified`；`pending → cancelled` | 核验后入库；取消原因必填 |
| 预订单 | `pending → verified`；`pending → cancelled` | 创建预占；取消或超时释放；核销转正式出库 |
| 盘点单 | `counting → submitted → completed`，或取消 | 完成时按差异生成相应库存流水 |
| 客服会话 | 创建、回复、指派、内部备注、状态更新 | 客户内容与内部备注分开处理 |

## 5. 非功能要求

| 维度 | 实现口径 |
| --- | --- |
| 一致性 | 事务、幂等键、版本校验和库存流水共同约束写入 |
| 安全 | 管理与客户端会话分离；受保护写接口校验权限和 CSRF |
| 可追溯 | 单据号、核验码、订单快照、库存流水和审计记录可查询 |
| 部署 | onebox 默认 SQLite；可选 MySQL 服务和受控迁移流程 |

外部短信、邮件、Webhook 只展示配置校验和失败保护，不实际对外发送。
