# Y-Link——智能库存与订单协同管理系统数据库设计说明书

## 1. 运行模式

默认 onebox 使用 SQLite 文件库；可选 MySQL 运行模式。TypeORM 实体清单在 `backend/src/config/data-source.ts`，初始化与增量 SQL 在 `backend/sql/`。表结构以实体和 SQL 为准，不以页面字段推断。

## 2. 核心表与主外键

| 数据域 | 主表 | 主键 | 关键外键/从表 |
| --- | --- | --- | --- |
| 商品 | `base_product` | `id` | `base_product_sku.product_id`；分类、主系列标签 |
| 标签 | `base_tag` | `id` | `rel_product_tag` 关联产品与标签 |
| 送货入库 | `biz_inbound_order` | `id` | `biz_inbound_order_item.order_id`；`supplier_id → sys_user` |
| 普通出库 | `biz_outbound_order` | `id` | `biz_outbound_order_item.order_id`；明细关联产品/SKU |
| 预订单 | `o2o_preorder` | `id` | `o2o_preorder_item`；`client_user_id → client_user` |
| 盘点 | `inv_stocktake` | `id` | `inv_stocktake_item.stocktake_id` |
| 客服 | 反馈会话、消息、附件 | 各自 `id` | 会话与消息/附件关联 |

## 3. 关键索引与约束

| 对象 | 索引/约束 | 用途 |
| --- | --- | --- |
| 产品 | `uk_base_product_code`；产品系列组合唯一；非负库存/价格 CHECK | 防止编码重复和不合法数量 |
| SKU | `uk_base_product_sku_code`、`uk_base_product_sku_barcode`、产品和商城列表索引 | 支持规格定位、扫码和商品列表 |
| 送货单 | 单号与核验码唯一；供应方、状态、软删除索引 | 避免重复核验并支持历史查询 |
| 预订单 | 单号、核验码唯一；`client_user_id + client_request_id` 唯一 | 防重复下单和按客户状态查询 |
| 盘点 | 盘点单号唯一；状态、创建时间、主键复合索引 | 支持状态列表和流程查询 |

## 4. 数据一致性

产品和 SKU 保留物理库存与预占库存；SKU 是规格选择后的库存口径。订单、送货单和库存单据的明细保存商品或规格快照，防止主数据变更篡改历史展示。送货核验、出库、预订单、盘点和退货通过服务层事务处理，库存变化由流水保留。

## 5. 迁移边界

MySQL 服务的启动与 SQLite 数据迁移是两件事。迁移流程要求备份、预检查、复制、校验、切换和回退。本轮迁移自动验证因夹具违反 `ck_account_lifecycle_event_type` 失败，不能作为迁移已验收的依据。
