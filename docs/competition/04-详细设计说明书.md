# Y-Link——智能库存与订单协同管理系统详细设计说明书

## 1. 供应送货与入库

供应送货提交要求带时区的 `expectedArrivalAt`、至少一条 `items[]` 明细；每条明细包含产品、可选 SKU 和正整数数量。服务端生成展示单号和核验码，状态为 `pending`。

```text
pending --核验码核验--> verified（入库并写库存流水）
pending --填写撤销原因--> cancelled
```

供货方只能处理归属单据；管理端核验、现场改动、已核验删除等操作还受角色、权限、CSRF 和高风险门禁限制。

## 2. 库存、盘点与普通出库

产品和 SKU 分别维护物理库存、预占库存；SKU 为规格销售的优先口径。创建普通出库时，服务端对明细、可用量和状态进行事务内校验，记录单据和库存流水。重试使用幂等键，修订使用版本校验；软删除、恢复和库存回补受订单状态及库存规则限制。

盘点单按范围创建，记录盲盘开关和明细：

```text
counting → submitted → completed
counting / submitted → cancelled
```

完成时根据差异调用共享记账逻辑生成盘盈、盘亏或报损流水。盲盘账面数由接口裁剪，不只依赖页面隐藏。

## 3. O2O 预订单

提交请求包含 `clientRequestId`、`isSystemApplied`、`pickupContact`、可选 `pickupAt`、备注和 `items[]`。服务端以 `clientUserId + clientRequestId` 唯一约束处理同一请求的重复提交，并保存名称、规格、价格、部门/工号等历史快照。

```text
pending --客户端/后台取消或超时--> cancelled（释放预占）
pending --管理端核销--> verified（关联正式出库）
verified --退货流程--> 按退货审核状态处理库存和订单
```

服务端在下单、改单、取消、核销、退货节点复核用户归属、商品、SKU、数量、库存和当前状态；客户端不能以页面参数直接改变库存。

## 4. 客服与治理

客户端创建会话、追加消息、查看自己的附件和会话；客服端查询、回复、指派、更新状态、维护问题字段和内部备注。管理写请求受认证、权限和 CSRF 保护，永久删除密码仅在服务端校验。错误响应和日志不输出密码、会话凭据或数据库连接信息。
