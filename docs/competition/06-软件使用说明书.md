# Y-Link——智能库存与订单协同管理系统软件使用说明书

> 面向第一次使用 Y-Link 的 Web 端评委。本文以可操作的界面路径说明管理端、供应端和客户端的完整闭环；菜单、状态和按钮名称以当前 Web 版本为准。

## 1. 阅读约定与演示边界

### 1.1 端别、入口与角色

Y-Link 的 Web 端由三个入口组成：

| 入口 | 地址 | 主要角色 | 用途 |
| --- | --- | --- | --- |
| 管理端 | `/login` | 管理员、操作员 | 商品、库存、入库、出库、O2O、报表、用户、配置、审计和客服 |
| 供应端 | 共享管理壳层中的 `/supplier-delivery`、`/supplier-history` | 供应方 | 新建送货单、查看历史送货单、在待入库阶段改单或撤销 |
| 客户端 | `/client/login`，登录后默认进入 `/client/mall` | 客户端用户 | 浏览商品、购物车、结算、订单、反馈和个人资料 |

管理端和供应端共用左侧导航壳层，但供应方只看到供货工作台；客户端使用独立的顶部/底部导航，不会看到管理端菜单。没有相应权限时，菜单项会被隐藏，直接输入地址也会被路由守卫拒绝。

### 1.2 “查看”与“写入”的演示规则

- 生产演示按只读操作纪律执行：可以打开页面、筛选、查看详情和阅读审计，但禁止新增、编辑、删除、下单、取消、核销、退货、上传、迁移和修改配置；这不是系统内置的生产专用只读机制。
- 只有本地 Docker 合成演示环境可以进行写入操作。本文中所有“点击保存/确认/提交”的步骤都默认在该环境中执行。
- 本地演示数据是合成数据，仍按真实业务规则处理：库存、订单状态、核销状态和审计记录会真实变化。
- 文中“发送通知”“短信/邮件/Webhook”仅指校验配置、生成站内事件或查看外发结果；不把外部通道写成已实际送达。

### 1.3 操作词说明

- **进入位置**：从左侧菜单、客户端导航或地址入口打开页面。
- **输入/选择**：填写文本、日期、数量、SKU、状态筛选或复选项；除特别说明外，数量使用正整数。
- **提交/确认**：点击页面按钮后，按弹窗中的二次确认继续；取消弹窗不会产生写入。
- **结果检查**：检查成功提示、状态标签、列表行、详情抽屉、库存数或审计记录。
- **异常处理**：看到 4xx、库存不足、权限不足或状态冲突时先停止重复提交，按本文“常见错误”处理。

### 1.4 本说明书中的高风险标记

> **高风险**：会改变库存、订单状态、账号生命周期、配置或数据库。请仅在本地合成环境中操作，并在提交前核对单号、SKU、数量和目标对象。

> **只读**：不会写业务数据，但可能返回敏感业务信息。本说明书要求生产演示只执行这类动作；账号本身可能仍具备写权限。

## 2. 演示账号与登录退出

### 2.1 生产演示账号（只读操作纪律）

> 仅作演示使用，请勿更改生产数据。生产演示账号可以具备写权限；“只允许查看”是评委必须遵守的操作纪律，不是系统内置的生产专用只读机制。登录后仅执行筛选、查看列表/详情等只读动作，人工避免点击任何新增、编辑、删除、提交或确认按钮。Markdown 源文件不保存生产凭据。

未提供生产供应端账号，不猜测、不补写。需要展示供应端写入流程时，切换到本地 Docker 合成演示环境并使用该环境已配置的供应方账号。

### 2.2 管理端登录

1. **进入位置**：打开 `/login`，或访问受保护管理端地址后等待跳转。
2. **输入/选择**：填写管理端登录账号和密码，按页面提示完成验证码（若页面显示）；密码输入过程保持遮蔽。生产演示账号可以正常提交登录，登录后仅执行筛选、查看列表/详情等只读动作，不得触发任何业务写操作；本地演示环境使用预置账号。
3. **提交/确认**：点击“登录”。不要在地址栏拼接 Token，也不要把 Cookie 复制给他人。
4. **结果检查**：成功后进入“工作台”；右上角显示当前用户，左侧菜单按权限显示。刷新页面仍保持会话，说明安全 Cookie 会话建立成功。
5. **异常处理**：
   - “账号或密码错误”：核对输入法、空格和环境，停止连续尝试。
   - “权限不足/页面不存在”：确认当前账号角色及权限，使用有授权的本地演示账号。
   - “请求过于频繁/暂时锁定”：等待页面提示的时间，不用脚本重复提交。

### 2.3 客户端登录

1. **进入位置**：打开 `/client/login`；首次访问 `/client/*` 也会跳转到此页。
2. **输入/选择**：在“登录”页填写姓名、手机号、邮箱或工号中的一种账号标识和密码；按页面要求填写图形验证码。没有账号时可切换“注册”；生产演示按操作纪律仅做查看，账号本身可能具备写权限，必须人工避开写操作。
3. **提交/确认**：点击“登录”。登录成功后若原来有待访问地址，会回到该地址，否则进入“商品大厅”。
4. **结果检查**：看到商品大厅、客户端导航和购物车摘要栏；“我的”页面可以查看当前账号资料。
5. **异常处理**：验证码过期点击验证码图片刷新；账号状态不可用时联系管理员，不要尝试绕过状态校验。

### 2.4 退出与会话安全

1. **进入位置**：点击右上角当前用户菜单（管理端）或客户端“我的”页的账户操作区。
2. **输入/选择**：选择“退出登录”；不要选择浏览器“清空所有站点数据”代替退出。
3. **提交/确认**：若出现确认框，点击“确认退出”。
4. **结果检查**：管理端回到 `/login`，客户端回到 `/client/login`；回退浏览器历史不能重新打开受保护页面。
5. **异常处理**：若退出后仍显示旧页面，刷新一次并重新访问入口；不要复用旧页面中的提交按钮。

## 3. 界面结构与导航

### 3.1 管理端公共结构

管理端页面通常包含：

1. 左侧菜单：按“业务操作、供货管理、基础资料、系统管理”分组；分组可展开，当前项高亮。
2. 顶部面包屑/页面标题：说明当前业务域和子页面。
3. 页面容器：标题、说明、筛选工具栏、统计卡、表格/卡片和分页。
4. 详情抽屉或弹窗：在不离开列表的情况下查看详情、修改或确认。
5. 全局消息：成功、警告和错误提示位于页面顶部或右上角。

页面在窄屏会切换为卡片布局；同一权限和状态规则不因屏幕宽度改变。

### 3.2 客户端公共结构

客户端包括商品大厅、我的订单、购物车和“我的”导航；订单详情、反馈列表和反馈详情会暂时收起底部导航，以便集中处理当前单据。商品大厅底部的悬浮购物车显示已选商品种类和结算入口。

## 4. 管理端操作手册

### 4.1 工作台：看概览、趋势和近期动态（只读）

1. **进入位置**：左侧“业务操作 → 工作台”，地址为 `/dashboard`。
2. **输入/选择**：在“结构占比”区域选择日期范围和订单类型；可切换商品榜的“合并”或“细分规格”视图。四宫格的今日/本月数字不随该区间筛选改变。
3. **提交/确认**：点击“查询”或日期控件的确认操作；这里是查询动作，不会写业务数据。
4. **结果检查**：核对三个结构占比图、趋势图、Top 产品、Top 客户和近期动态是否都显示同一筛选范围。点击排行或动态可打开钻取抽屉/出库单详情。
5. **异常处理**：
   - 图表为空：确认日期范围内是否有数据，再点击“刷新”。
   - 数字和列表不一致：检查筛选是否包含同一订单类型、统计日和软删除状态。
   - 近期动态指向已永久删除单据时，只能查看审计展示，不能打开单据详情。

### 4.2 产品中心：产品、SKU、规格、标签

![图 2 产品中心](../../output/competition-work/demo-media/browser-window-screenshots-v2/02-admin-products.png)

图 2 说明：产品中心以列表和详情工作台展示产品、规格、价格、库存摘要及标签入口。

1. **进入位置**：左侧“基础资料 → 产品中心”，地址为 `/base-data/products`。
2. **输入/选择**：用关键字、启停状态或标签筛选；点击一行的“编辑/查看”进入产品详情。检查产品名称、商品编码、启用状态、缩略图、标签和 SKU 规格组；多 SKU 商品逐行核对 `skuCode`、规格文本、默认售价、折扣、推荐和排序。
3. **提交/确认**：本地环境中点击“新增产品”或“编辑”后填写必填字段，先保存产品基础字段，再在规格矩阵中保存 SKU。保存前确认同一产品的 SKU 编码和规格文本不重复。
4. **结果检查**：列表回到当前页，出现成功提示；重新打开详情确认 SKU、标签和价格仍然存在。若修改了库存，进入“库存管理 → 当前库存”核对 SKU 汇总。
5. **异常处理**：
   - SKU 重复：修改编码或规格文本后再保存。
   - 商品已被订单或库存引用：按页面提示停用，不尝试物理删除。
   - 客户端仍看不到商品：进入“线上预订 → 产品中心”确认基础启用且客户端展示为“上架”。

**数据影响**：产品、SKU、价格、标签和展示字段会影响商城展示、购物车校验和后续订单快照；生产演示按操作纪律仅做查看，账号本身可能具备写权限，必须人工避开写操作。

### 4.3 标签管理

1. **进入位置**：左侧“基础资料 → 标签管理”，地址为 `/base-data/tags`。
2. **输入/选择**：搜索标签名称；本地环境点击“新增标签”或列表中的“编辑”，填写名称、颜色/排序等页面字段；产品详情中可选择已有标签。
3. **提交/确认**：点击“保存”或“删除”，删除操作按弹窗提示二次确认。删除前确认没有把标签作为商城筛选或报表条件使用。
4. **结果检查**：刷新列表，确认标签状态/名称变化；回到产品中心检查关联产品；报表中的标签筛选应能使用新值。
5. **异常处理**：名称重复或为空时按校验提示修正；删除失败时先解除产品关联，不重复点击。

### 4.4 分类与库位

1. **进入位置**：左侧“库存管理 → 分类与库位”，地址为 `/inventory/master-data`。
2. **输入/选择**：在“分类”或“库位”区域点击“新增/编辑”。分类填写两位数字编码和名称；库位填写位置编码（例如区-架-层格式）和可选名称。
3. **提交/确认**：点击“保存”。停用分类或库位时在确认框选择“确认停用”；系统只停用，不物理删除。
4. **结果检查**：列表显示启用/停用状态；产品编辑器和盘点范围下拉框能看到最新选项。已关联商品的分类编码不得修改。
5. **异常处理**：编码格式错误或已被占用时更换编码；关联商品导致编码不可改时，新增替代分类并按业务流程迁移，不直接改历史编码。

### 4.5 当前库存

![图 3 当前库存](../../output/competition-work/demo-media/browser-window-screenshots-v2/03-admin-inventory.png)

图 3 说明：当前库存按商品/SKU 展示现有库存、预订占用和可用量，可继续进入库存流水追溯。

1. **进入位置**：左侧“库存管理 → 当前库存”，地址为 `/inventory/stocks`。
2. **输入/选择**：输入商品、SKU、条码或库位关键字，选择分类/状态；点击“查询”。
3. **提交/确认**：查询不写数据。需要查看规格时，点击商品行的“查看规格/详情”。
4. **结果检查**：核对 `currentStock`、`preOrderedStock` 和可用量（当前库存减预订占用，最低为 0）。当前且启用 SKU 才计入商品汇总；停用或历史规格应单独标识。
5. **异常处理**：库存和商品详情不一致时先刷新，再查看“库存流水”；不要直接在浏览器修改响应数据。

### 4.6 扫码作业：采购入库、其他出库、退货入库、报损与调整

![图 4 扫码作业](../../output/competition-work/demo-media/browser-window-screenshots-v2/22-admin-inventory-scan.png)

图 4 说明：扫码作业以条码/SKU 编码识别规格，再按单据类型和数量记账。

1. **进入位置**：左侧“库存管理 → 扫码作业”，地址为 `/inventory/scan`。
2. **输入/选择**：选择作业类型（采购入库、其他出库、退货入库、报损出库或库存调整）；扫描或输入条码/SKU 编码并回车，确认系统识别的商品、规格和库位；填写正整数数量和备注。
3. **提交/确认**：点击“加入明细/保存草稿”，核对明细后点击“提交单据”，在二次确认框选择“确认提交”。
4. **结果检查**：出现库存单据号（`KD...`）和成功提示；进入“当前库存”检查新库存，进入“库存单据”检查状态，进入“库存流水”检查操作类型、前后库存和操作人。
5. **异常处理**：
   - 扫码无结果：清理前后空格，确认扫的是当前 SKU 条码或编码。
   - 可用量不足：减少数量或改用正确的库存场景；不重复提交。
   - 同一 SKU 已有未完成盘点单：先处理盘点冲突。
   - 网络中断：记录页面是否显示“结果未知”，刷新单据列表确认是否已经落库，再决定是否重试。

**数据影响**：这是库存写入操作，所有调整均经过库存台账并写库存流水；生产环境禁止操作。

### 4.7 库存单据

1. **进入位置**：左侧“库存管理 → 库存单据”，地址为 `/inventory/docs`。
2. **输入/选择**：按单据号、类型、状态、日期和操作人筛选；点击某行打开“单据明细”。
3. **提交/确认**：本地环境中仅对允许作废的未完成单据点击“作废”，确认影响范围；已记账单据不得用列表按钮绕过库存流水。
4. **结果检查**：状态标签、明细数量和库存流水引用一致；作废后重新查看当前库存确认回滚/不再生效符合页面说明。
5. **异常处理**：已完成或被订单/盘点引用的单据不能作废；若按钮禁用，转到对应订单或盘点流程处理。

### 4.8 库存盘点：建单、盲盘、差异和调账

1. **进入位置**：左侧“库存管理 → 库存盘点”，地址为 `/inventory/stocktakes`。
2. **输入/选择**：点击“新建盘点单”，选择范围“全部商品、按分类、按库位或指定商品”；指定商品可扫描/输入条码；按需要勾选“盲盘”，填写备注。
3. **提交/确认**：点击“创建”，进入盘点作业；逐行扫描或填写实盘数量，保存阶段结果；完成后点击“提交盘点结果”，提交后进入“待确认”，再次核对差异并确认调账。
4. **结果检查**：盘点单号格式为 `PD...`，状态按“盘点中 → 待确认 → 已完成”推进；差异行显示账面数、实盘数和调整数量；“库存流水”出现盘点调整记录。
5. **异常处理**：
   - 规格已被其他未完成盘点单占用：结束或处理原盘点单后再建单。
   - 盲盘看不到账面数：这是设计行为，按实盘数量完成；不要通过开发者工具读取账面数。
   - 提交后发现漏盘：按页面“退回重新盘点”流程处理，不直接改数据库。

**高风险**：确认调账会改变实际库存，提交前必须由现场人员复核数量和差异原因。

### 4.9 库存流水

1. **进入位置**：左侧“库存管理 → 库存流水”，地址为 `/inventory/logs`。
2. **输入/选择**：按商品、SKU、条码、操作人、备注、操作类型和日期筛选；点击“查询”，需要交付时点击“导出 Excel”。
3. **提交/确认**：预览导出范围后确认导出；导出只读当前筛选，不改变库存。
4. **结果检查**：关注操作类型、来源单号、`stockDelta`、变更前后库存、SKU 快照和操作人；销售出库等历史类型的 `changeQty` 可能以出库方向为正，展示列以带符号的库存变化为准。
5. **异常处理**：发现库存跳变时先按来源单号打开单据，再检查是否存在回补、恢复或盘点调整；不要只看商品主表总数。

### 4.10 供应入库（管理端核验）

![图 5 供应方送货录入](../../output/competition-work/demo-media/browser-window-screenshots-v2/04-supplier-delivery.png)

图 5 说明：供应方工作台录入送货明细、预计送达时间和备注，提交后生成送货单与核验二维码。

![图 6 管理端入库管理](../../output/competition-work/demo-media/browser-window-screenshots-v2/11-admin-inbound.png)

图 6 说明：管理端入库管理展示待入库单据池、详情、数量核对和核验入口。

1. **进入位置**：管理端选择“入库管理”进入 `/inbound-manage`；需要扫码时选择“扫码入库”进入 `/inbound-scan`。
2. **输入/选择**：在送货单池选择“全部/待入库/已入库”，可按单号或供货方搜索；打开详情核对 `showNo`、核验码、供应方、预计送达时间、商品和数量。扫码页可扫描二维码或输入送货单号/核验码。
3. **提交/确认**：核对现场实物后，点击“核验入库/确认入库”；如需现场改单，先修改明细并保存，再进行核验。二次确认时检查将写入商品和 SKU 库存。
4. **结果检查**：状态由“待入库”变为“已核验/已入库”；“当前库存”增加对应数量，“库存流水”出现入库记录；送货单详情保留核验时间和操作人。
5. **异常处理**：
   - 核验码无效：回到供应方历史单据，用完整送货单号或二维码重新查询。
   - 单据已撤销/已删除/已核验：不能再次核验，先刷新状态。
   - 数量不符：使用现场改单流程记录实际数量，不要直接在库存页补一笔无来源入库。

**高风险**：核验入库会实际增加库存；已入库送货单的删除是冲销治理，需要完整单号、永久删除密码和库存一致性校验，仅在合成环境演示。

### 4.11 普通出库开单与出库单治理

![图 7 普通出库开单](../../output/competition-work/demo-media/browser-window-screenshots-v2/21-admin-order-entry.png)

图 7 说明：出库单列表/详情工作台支持筛选、查看、修订、软删除和恢复；新增开单从“出库开单”进入。

1. **进入位置**：左侧“业务操作 → 出库开单”，地址为 `/order-entry`；历史单据在“出库单列表”，地址为 `/order-list`。
2. **输入/选择**：在开单页选择客户类型、客户/部门、产品和当前启用 SKU；填写正整数数量、人工单价、备注和必要的部门字段。单 SKU 商品可自动选中，多 SKU 必须明确选择；`defaultPrice` 只作为预填。
3. **提交/确认**：核对明细、总数量和总金额，点击“提交出库单”；确认幂等提示和库存预检。不要连续点击提交按钮。
4. **结果检查**：成功提示包含业务单号；在“出库单列表”搜索该单号，打开详情检查 SKU/规格快照、金额、库存模式和审计记录；“当前库存”与“库存流水”应同步减少可用库存。
5. **异常处理**：
   - 库存不足：检查 `currentStock - preOrderedStock`，减少数量或更换 SKU。
   - 商品/规格失效：返回产品中心选择当前启用商品，不让旧草稿猜测映射。
   - 订单号冲突或版本冲突：刷新列表，以最新版本重新编辑。
   - 需要删除：仅可先软删除；`manual_applied` 单据按弹窗选择是否回补库存，恢复时会重新校验库存；永久删除受权限和永久删除密码限制。

出库列表还支持详情抽屉、内容编辑、修订时间线、合规标记和订单合并。合并必须先“预览”再“提交”，来源单会成为只读子单，不会再次扣库存；生产环境禁止这些写操作。

#### 4.12.1 维护线上商品

1. **进入位置**：左侧“线上预订 → 产品中心”，地址为 `/o2o-console/products`。
2. **输入/选择**：搜索产品或标签，打开“编辑”；确认“基础启停”“客户端展示”“规格推荐”“详情说明”和限购字段。基础启用且客户端展示上架后，商品才会出现在客户端大厅。
3. **提交/确认**：本地环境点击“保存”或批量“上架/下架”，在确认框核对影响商品范围。
4. **结果检查**：列表状态更新；切换客户端或刷新商品大厅，检查商品、图片、规格、售价和可用库存。订单中的价格仍以提交时快照为准。
5. **异常处理**：商品仍不显示时检查基础启停、客户端上架、当前启用 SKU、缩略图和库存；不要在客户端手动改价。

#### 4.12.2 查看订单池和订单详情

1. **进入位置**：左侧“线上预订 → 订单查询”，地址为 `/o2o-console/orders`。
2. **输入/选择**：选择“待提货/已核销/已取消/退货相关”等分栏，按订单号、核销码、用户名、商品、账号类型、部门或工号筛选。
3. **提交/确认**：点击“查询”；选中订单后可复制核销码、刷新状态、填写商家留言或更新合规状态。取消订单和删除已取消订单属于高风险动作，必须在本地确认。
4. **结果检查**：详情核对订单状态、取货时间、总金额/数量、明细、正式出库单关联、退货申请和处理节点。
5. **异常处理**：订单找不到时先清空筛选并确认分栏；状态正在变化时刷新详情，不要对旧状态重复取消。

#### 4.12.3 现场核销

1. **进入位置**：左侧“线上预订 → 预订单核销”，地址为 `/o2o-console/verify`。
2. **输入/选择**：扫描或粘贴取货码、退货码、业务单号或二维码链接，按回车查询；核对客户、商品、数量、取货时段和订单状态。
3. **提交/确认**：待核销订单可先点击“现场改单”调整数量/明细并保存；确认无误后点击“核销”，退货场景则选择“拒绝退货”并填写原因或按流程确认。
4. **结果检查**：取货核销成功后状态变为已核销，库存占用释放并生成/关联正式出库记录；退货成功后显示退货数量、退货码和处理人。
5. **异常处理**：码无效、已使用、已取消或已过期时停止操作，回订单池刷新真实状态；拒绝退货必须填写清晰原因，不使用空白或猜测原因。

### 4.14 用户、客户端用户与权限

1. **进入位置**：左侧“系统治理 → 用户中心”，地址为 `/system/users`；客户端用户在同一工作台的“客户端用户”标签或 `/system/client-users`。
2. **输入/选择**：使用搜索、角色/账号身份、状态、部门、工号筛选；本地环境新增或编辑时填写账号、显示名、联系方式、角色/部门、状态和初始密码。
3. **提交/确认**：点击“保存”。修改密码需填写新密码和确认密码；注销、恢复、永久删除按生命周期弹窗填写原因、逐字确认和永久删除密码。
4. **结果检查**：列表显示 `enabled/disabled` 或计算后的账号状态；重新搜索并打开详情，确认权限和最后更新时间。客户端账号与管理端账号是两个域，不能混用。
5. **异常处理**：
   - 账号被业务关联而不能永久删除：保留账号并停用，不能强制清理历史关联。
   - 角色没有菜单：检查权限码而不是只看角色名称。
   - 忘记密码：使用受控“修改密码”入口；不要在数据库或浏览器本地改密码。

**高风险**：注销、恢复和永久删除会影响登录会话、订单、客服和通知关联；永久删除属于不可逆治理动作，仅在合成数据中演示。

### 4.15 系统配置

1. **进入位置**：左侧“系统治理 → 系统配置”，地址为 `/system/configs`。
2. **输入/选择**：在目标 section 展开表单，先阅读当前值和说明，再修改流水号、O2O 规则、客服配置、验证码通道、部门树或目录导入预览等字段。外部 URL、Webhook 和通道地址只能填写经过批准的安全地址。
3. **提交/确认**：本地环境点击对应“保存/更新/导入”按钮；目录导入先“预览”，确认部门路径、同名冲突和行数后再正式提交。
4. **结果检查**：保存成功后刷新页面，确认回显与预期一致；客户端订单部门选项、客服工作台和通知事件使用新配置。外部发送是否成功需看通知外发记录，不能仅凭保存成功推断已送达。
5. **异常处理**：
   - 保存后回显旧值：刷新并检查当前配置 key；若仍旧，查看权限和审计。
   - 部门路径冲突：修正唯一完整路径后重新预览。
   - 通知/验证码通道不可用：检查配置校验和后端外发结果，不反复点击“发送”。

### 4.16 审计日志

1. **进入位置**：左侧“系统治理 → 审计日志”，地址为 `/system/audit-logs`。
2. **输入/选择**：选择业务类别、操作类型、目标对象，输入目标 ID 或设置时间范围；点击“搜索”。
3. **提交/确认**：只读查询；有 `audit_logs:export` 权限时点击“导出”，在确认弹窗检查筛选条件后导出。
4. **结果检查**：关注操作者、动作编码、目标对象、时间、结果和脱敏详情；通知事件按 eventId 聚合，不把规则命中当作外部送达。
5. **异常处理**：找不到记录时扩大时间范围并清空目标筛选；敏感字段被脱敏是预期行为，不要求恢复原文。

### 4.17 数据库迁移助手

1. **进入位置**：左侧“系统治理 → 数据库迁移助手”，地址为 `/system/db-migration`。
2. **输入/选择**：先阅读风险提醒和当前数据库状态；在“一键自动迁移”表单填写隔离目标 MySQL 主机、端口、用户名、密码、独立空库名称和迁移说明。目标库必须是专用、空的 `utf8mb4` 库，不能填写生产库。
3. **提交/确认**：先点击“测试连接”，确认版本、字符集、权限和目标为空；再点击“创建自动任务”，在二次确认中确认维护窗口。高级/应急步骤只在演练脚本或管理员明确授权时使用。
4. **结果检查**：任务按 UI 语义从“待执行/排队中”进入“执行中”，维护期间普通写入会被只读屏障拒绝；重启和校验阶段显示“等待重启/校验中”，完成后显示“已成功”，页面显示运行时 MySQL 已生效，容器完成重启，健康状态恢复。直接查看目标库和导出摘要核对结构、数据、约束、自增序列与原库一致。
5. **异常处理**：
   - 连接、版本、字符集或权限预检失败：修正目标库后重试，不进入迁移写入。
   - 目标库非空：停止任务，不清理目标既有数据。
   - 任务失败/回退：保留任务 ID、状态和审计，确认 SQLite 仍在工作；不要手工删除 maintenance、cutover 或 runtime override 文件。
   - 本地没有 Docker/Compose 或 daemon 未启动：这是验证阻断，不把界面打开当作迁移通过。

**高风险**：数据库迁移可能影响全站数据源、维护状态和容器重启，生产环境不得按本文自行演示；只可使用隔离验收 Compose 和脱敏凭据。

## 5. 供应端操作手册

### 5.1 新建送货单

1. **进入位置**：供应方登录后进入“供货工作台 → 录入”，地址为 `/supplier-delivery`。
2. **输入/选择**：逐行选择商品，填写数量；选择必填“预计送达时间”，可填写备注。同一商品可分多行录入，提交时会合并数量。
3. **提交/确认**：点击“提交送货单”，确认弹窗中的商品、数量和预计送达时间，点击“确认生成”。
4. **结果检查**：出现送货单号、状态“待入库”和核验二维码；保存送货单号/核验码供管理端使用。若二维码暂未显示，记录单号后到历史单据补查。
5. **异常处理**：商品目录仍在加载、数量为 0 或未填预计送达时间时不能提交；刷新目录后重新选择，不复制旧页面的失效商品 ID。

### 5.2 历史单据、改单与撤销

1. **进入位置**：供货工作台切换“历史单据”，地址为 `/supplier-history`。
2. **输入/选择**：按送货单号或状态筛选；打开待入库单据，核对商品、数量、预计送达时间和备注。
3. **提交/确认**：仅对自己的“待入库”单据点击“改单”或“撤销”，保存新明细/时间后确认；撤销需二次确认。
4. **结果检查**：改单后详情显示新版本和更新时间；撤销后状态为“已撤销”，管理端入库池不再把它当作待入库单。
5. **异常处理**：已核验、已撤销或已删除单据不能再改；列表权限与服务端归属校验同时生效，不能通过修改 URL 查看他人单据。

3. **提交/确认**：点击“+ 加购”或详情中的“加入购物车”；无需再次确认，但看到成功提示后再继续选择。
4. **结果检查**：底部悬浮购物车的种类/数量更新；展开购物车检查商品名称、规格、售价和可用库存。
5. **异常处理**：商品已下架、规格停用或库存变化时，按提示刷新目录或调整数量；不要把客户端显示的旧库存当成最终可下单库存。

### 6.2 购物车：勾选、调整和删除

![图 14 客户端购物车](../../output/competition-work/demo-media/browser-window-screenshots-v2/18-client-cart.png)

图 14 说明：购物车支持全选、批量删除、失效商品分组和进入结算前的库存校验。

1. **进入位置**：点击悬浮购物车“进入购物车”，或底部导航“购物车”，地址为 `/client/cart`。
2. **输入/选择**：勾选要结算的有效商品，使用“+/-”或数量输入调整数量；失效商品先选择“移除/重新选择”。
3. **提交/确认**：需要删除时点击“批量删除/移除”，确认弹窗；准备下单时点击“去结算”。
4. **结果检查**：合计数量和金额只包含已勾选有效商品；结算页能打开且显示最新商品明细。
5. **异常处理**：库存或规格变化时，页面会阻止结算并提示调整；返回商城刷新后再勾选，不反复点击“去结算”。

### 6.3 结算：提货信息、归属和时段

![图 15 客户端确认订单](../../output/competition-work/demo-media/browser-window-screenshots-v2/33-client-checkout.png)

图 15 说明：确认订单页在提交前重新校验库存、限购和账号归属，并要求选择提货时间。

1. **进入位置**：购物车点击“去结算”，地址为 `/client/checkout`。
2. **输入/选择**：填写提货人；部门账号按页面要求确认“金蝶系统是否已申请”；选择到店取货日期和时段；可填写订单备注。下单归属由账号类型自动判定，客户端不能手动切换。
3. **提交/确认**：检查商品、SKU、数量、总金额、提货人和时段，点击“提交订单/确认下单”；等待服务端校验完成，不重复点击。
4. **结果检查**：出现成功提示并进入订单详情/订单列表；订单状态为“待提货”，生成取货码/二维码；购物车中已提交商品被清理或数量同步。
5. **异常处理**：库存、限购或目录刷新失败时，页面会阻止提交；返回购物车调整。若请求结果未知，先去“我的订单”查订单号再决定是否重试。

**高风险**：提交会占用可用库存并创建预订单；演示时使用专门的合成订单，避免影响其他演示路径。

### 6.4 我的订单：列表、详情、取消与退货

![图 16 客户端订单详情](../../output/competition-work/demo-media/browser-window-screenshots-v2/31-client-order-detail.png)

图 16 说明：订单详情集中展示二维码、取货时段、状态节点、商品快照和退货服务。

1. **进入位置**：底部导航“我的订单”，地址为 `/client/orders`；点击任一订单进入 `/client/orders/:id`。
2. **输入/选择**：在订单列表切换全部、待提货、已核销、已取消等状态，按订单号、核销码、部门、工号或归属搜索；详情中核对状态、取货时间、商品、单价和金额。
3. **提交/确认**：待提货且符合规则时点击“取消订单”，确认取消原因；已核销订单在“退货服务”中选择商品和退货数量，填写退货原因后提交退货申请并确认。
4. **结果检查**：取消后订单移入已取消分栏，预订占用释放；退货提交后出现退货申请、待处理数量和退货码，状态节点更新。核销由工作人员在管理端完成，客户端只展示核销结果和二维码。
5. **异常处理**：
   - 取消按钮不可用：订单已核销、已取消、已过期或不在允许时间内，刷新详情确认。
   - 可退数量为 0：检查是否已有待处理退货或已全部退回，不重复提交。
   - 订单列表和详情不一致：刷新详情，再回列表刷新；不要使用旧二维码。

### 6.5 反馈与个人资料

1. **进入位置**：底部导航“我的 → 反馈会话”，地址为 `/client/feedback`；个人资料在 `/client/profile`。
2. **输入/选择**：点击“进入新建反馈页”，选择普通建议或专业 BUG，填写标题、问题类型/分类、期望结果、实际结果、复现步骤、关联订单、联系偏好和标签；个人资料页查看或按权限编辑姓名、联系方式和部门信息。
3. **提交/确认**：点击“提交反馈并进入会话”；详情页可继续补充、确认解决或评价客服回复。不要把内部排查结论写进面向客服的消息。
4. **结果检查**：反馈列表出现新会话；详情页显示四阶段处理进度、最近动作、Issue 字段和客服回复。客服离线时可以先看常见问题，消息是否实时到达以会话刷新结果为准。
5. **异常处理**：附件大小/类型不符合时删除附件后重试；会话已关闭时按页面提示新建反馈或申请继续处理；网络断开时先刷新详情确认是否已创建。

## 7. 三条跨角色完整演示路径

### 路径 A：供应送货 → 管理核验入库 → 库存追溯

1. 供应方在“供货工作台 → 录入”选择预置商品，填写数量和预计送达时间，点击“确认生成”。
2. 供应方记录送货单号/二维码，在“历史单据”确认状态为“待入库”。
3. 管理端进入“入库管理”，在待入库池搜索该送货单；打开详情核对商品、数量和供应方。
4. 管理端扫码或输入核验码，必要时先现场改单，点击“确认入库”。
5. 管理端检查状态变为已核验/已入库；在“当前库存”检查数量增加，在“库存流水”检查入库来源、前后值和操作人。
6. 异常演示：使用另一张待入库合成单输入错误核验码，确认系统拒绝且库存不变；不要用生产单据做反例。

### 路径 B：管理建档上架 → 客户下单 → 管理核销

1. 管理端在“产品中心”确认商品、当前启用 SKU、价格、标签和库存；在“线上预订 → 产品中心”确认基础启用且客户端展示上架。
2. 客户端在“商品大厅”搜索商品，选择规格并“加入购物车”；在购物车勾选商品进入结算。
3. 客户填写提货人、部门申请状态、日期和时段，点击提交订单，进入订单详情查看待提货状态和取货码。
4. 管理端在“订单查询”按订单号/核销码定位订单，核对客户、商品、数量、金额和取货时间。
5. 管理端进入“O2O 核销台”，扫描取货码，确认明细后点击“核销”。
6. 客户端回到“我的订单”刷新详情，检查状态、核销时间和正式出库信息；管理端再检查库存流水和审计。

### 路径 C：客户端反馈 → 客服接单回复 → 客户确认解决

1. 客户端进入“反馈会话 → 新建反馈”，填写标题、问题类型、关联订单和复现步骤，提交后进入反馈详情。
2. 管理端进入“客服工作台”，按订单号或标题搜索，打开会话并点击“接单/接管”。
3. 客服在 Issue 字段补充分类和期望结果，在“客服回复”输入面向客户的处理说明后点击“发送”；排查结论写入“内部备注”。
4. 客服按需要调整优先级、转派或把状态改为处理中/已解决，确认列表与详情同步。
5. 客户端刷新反馈详情，检查最近动作和回复；若问题已解决，点击“确认解决/评价”；若未解决，点击“继续反馈”补充现象。
6. 异常演示：客服未接单时尝试回复，确认页面阻止发送；接单后再发送，验证权限和状态门禁。

## 8. 常见错误与处理表

| 现象 | 先检查 | 正确处理 |
| --- | --- | --- |
| 页面显示“权限不足” | 当前账号角色、权限码、入口是否属于另一端 | 退出并使用对应演示账号；生产环境不申请临时写权限 |
| 列表为空 | 关键字、日期、状态、分页和当前端别 | 点击“重置/清空”，再查询；不要猜测单号 |
| 库存不足/库存变化 | 当前库存、预订占用、SKU 是否当前且启用 | 刷新目录，调整数量或选择正确 SKU；不重复提交 |
| 核验码无效/已使用 | 订单或送货单真实状态、码是否完整 | 回到订单池/历史单据复制新码，先刷新状态 |
| 订单提交结果未知 | 订单列表是否已经生成新单 | 先查订单再重试；保持原幂等意图，不连续点击 |
| 版本冲突/内容已更新 | 详情中的更新时间和编辑版本 | 放弃旧弹窗，刷新后按最新内容重新编辑 |
| 送货单不能修改 | 是否已核验、撤销或删除，是否本人单据 | 只有本人待入库单可改单；已入库走管理端现场流程 |
| 报表预览与导出不一致 | 报表类型、筛选和导出字段 | 重新查询并在导出预览核对；不要按当前页手工累加总数 |
| 图片或附件打不开 | 上传目录、文件类型和权限 | 刷新并检查页面错误；不在 URL 中拼接 Token |
| 客服消息未实时出现 | SSE 在线状态、会话详情刷新 | 手动刷新确认消息；不把“在线”当成外部送达证明 |
| 配置保存后不生效 | config key、权限、刷新后的回显和审计 | 重新加载配置并查看审计；通知通道另查外发记录 |
| 迁移任务失败 | 目标库版本、字符集、权限、是否为空、Docker 状态 | 保留任务证据，确认原库仍工作；不要手工删除恢复文件 |

## 9. 禁止事项与安全提醒

1. 不在 Markdown、截图、日志、工单或聊天中记录真实生产用户名、密码、Token、Cookie、Webhook 密钥或数据库密码。
2. 不在生产环境点击新增、编辑、删除、下单、取消、核销、退货、上传、迁移和配置修改按钮；生产演示按操作纪律仅做查看，账号本身可能具备写权限，必须人工避开写操作。
3. 不通过 URL query 传递访问 Token，不使用开发者工具篡改响应、库存、权限或订单状态。
4. 不重复点击写入按钮，不在结果未知时直接创建新幂等键；先去列表和详情确认是否已落库。
5. 不把停用/历史 SKU 当作当前可用 SKU，不把客户端展示价格当作历史订单价格；历史订单以快照字段为准。
6. 不直接删除数据库文件、迁移标记、维护状态、运行时覆盖或上传目录；迁移失败按页面和受控救援流程处理。
7. 不把通知配置保存成功描述为短信、邮件或 Webhook 已实际送达；只能依据外发记录和真实返回结果说明。
8. 不在没有权限、永久删除密码或业务确认的情况下执行账号注销、永久删除、已入库送货单冲销、订单永久删除和批量删除。
9. 不将验收 Compose、临时 MySQL、测试卷和合成账号连接到生产数据；数据库迁移目标必须是隔离专用空库。
10. 演示结束后退出所有会话，清理本地合成数据和临时下载文件；不要把截图中的二维码当作可长期使用的凭证。
