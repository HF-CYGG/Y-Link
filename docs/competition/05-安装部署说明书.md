# Y-Link——智能库存与订单协同管理系统安装部署说明书

## 1. 部署对象

本说明书对应固定基线 `b149f945ad4702bc56487955ac2e2a0b8e359e2a`。onebox 使用 `Dockerfile.onebox`、`compose.onebox.yml` 和 `docker/onebox/entrypoint.sh`：同一容器内提供静态页面、Nginx 反向代理和 Express API，默认数据库为持久化 SQLite。

准备 Docker Engine、Docker Compose v2 和可写的数据目录。比赛录制只使用本地合成数据；不要导入生产库、上传文件或生产环境变量。

## 2. SQLite onebox 启动

在冻结源码副本根目录执行：

```powershell
Copy-Item .env.onebox.example .env
# 在 .env 中仅填写本地私有强密码 INIT_ADMIN_PASSWORD；不要提交 .env
docker compose -f compose.onebox.yml up -d --build
docker compose -f compose.onebox.yml ps
```

`INIT_ADMIN_PASSWORD` 为必填项，镜像会拒绝历史弱口令。`Y_LINK_PORT` 默认是 `8080`；可通过 `.env` 改为未占用的本地端口。容器健康检查请求 `http://127.0.0.1/health`，对外检查地址为 `http://127.0.0.1:<Y_LINK_PORT>/health`，预期 HTTP 200 且 `status` 为 `UP`。

还应分别打开管理端、客户端和供应端入口，使用本地演示账号完成登录检查。公开健康检查不应返回数据库拓扑或凭据。

## 3. 本地私密配置

| 配置项 | 用途 | 处理要求 |
| --- | --- | --- |
| `INIT_ADMIN_PASSWORD` | 初始化管理员密码 | 本地 `.env` 或部署平台密钥；必填，不入库 |
| `PERMANENT_DELETE_PASSWORD` | 永久删除服务端门禁 | 演示可留空；留空时永久删除被拒绝 |
| `INVITE_CODE_PEPPER`、验证码/云服务密钥 | 邀请码及外部服务保护 | 仅私密注入；比赛环境不调用真实第三方 |
| `Y_LINK_PORT` | onebox 映射端口 | 仅本机选择空闲端口 |
| 数据卷 | SQLite 数据和上传文件 | 录制前建立快照，录制后保留供复查 |

`.env.onebox.example` 只是字段模板。不得将生产账号、生产数据库地址、Cookie、Token 或真实密钥写入 `.env`、镜像、文档截图或录屏。

## 4. MySQL 叠加与迁移边界

`compose.onebox.mysql.yml` 只增加内部网络中的 MySQL 8.4 服务，不发布 MySQL 宿主机端口。复制 `.env.onebox.example` 后，填写本地私有的 `MYSQL_PASSWORD` 与 `MYSQL_ROOT_PASSWORD`，再启动：

```powershell
docker compose -f compose.onebox.yml -f compose.onebox.mysql.yml up -d mysql
docker compose -f compose.onebox.yml -f compose.onebox.mysql.yml ps
```

叠加 Compose 不会自行完成 SQLite 到 MySQL 的业务数据迁移。迁移由系统数据库维护流程执行，必须经过备份、预检查、复制、校验、切换和回退控制。本轮 `npm run verify:db:migration` 未通过，原因是全实体 SQLite 迁移夹具写入的 `account_lifecycle_event_type` 触发 `ck_account_lifecycle_event_type` 约束；因此比赛视频不展示“迁移成功”，也不在任何生产库执行迁移。

## 5. 演示数据快照与恢复

录制前先由 `docker volume ls` 确认本次 Compose 创建的数据卷名，再备份 SQLite 数据卷和上传卷。以下 `<data-volume>`、`<uploads-volume>` 与 `<backup-dir>` 必须替换为本机实际值：

```powershell
docker run --rm -v <data-volume>:/data -v <backup-dir>:/backup alpine tar -C /data -czf /backup/onebox-data.tgz .
docker run --rm -v <uploads-volume>:/uploads -v <backup-dir>:/backup alpine tar -C /uploads -czf /backup/onebox-uploads.tgz .
```

每段录制前停止 `ylink` 容器，再向对应卷恢复同一份归档，启动容器并重新检查 `/health` 和三个登录入口。恢复会覆盖该卷当前内容，只能对明确的本地演示卷执行；录制结束保留容器、数据卷和快照，不执行 `down -v`。
